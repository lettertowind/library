# Pandas 数据合并与重塑：merge 与 join 总结

## 一、课程主题与概念定位

- SQL 学习者常说的“连接查询”，在 pandas 中对应“数据合并与重塑”。
- “合并与重塑”指将多个表按某种规则组合起来，或重新组织成新的数据结果。
- 本节课重点总结 `merge` 的常用参数，并简要介绍 `join` 的用法与局限。
- 课程中列出的 `merge` 参数是常用参数，不是全部参数；部分参数在上一节课已介绍，本节课做系统总结。

## 二、merge 的核心参数

### on 参数：指定合并列对齐

`on` 用于指定左右两个表进行合并时所依据的列名，核心要求是：

- 左右表必须存在相同的列名。
- 通过同名列进行对齐合并。
- 可用单列，也可用多列列表。

示例表结构：

- 左表 `left`：
  - 索引：`0, 1, 2, 3`
  - 列：`a, b, k1, k2`
- 右表 `right`：
  - 索引：`0, 1, 2, 3`
  - 列：`c, d, k1, k2`

因为左右表都包含 `k1`、`k2`，所以可以按这两个字段合并：

`pd.merge(left, right, on=['k1', 'k2'])`

讲解中用 Excel 的 `VLOOKUP` 作类比：需要找到两个表都存在的字段，用该字段把右表信息匹配到左表中。`merge` 的 `on` 就是承担这个“对齐列/连接字段”的作用。

### how 参数：指定连接类型

`merge` 未指定 `how` 时，默认执行内连接。

- **内连接 `inner`**
  - 默认连接方式。
  - 取左右表中都存在的、相交的部分。
  - 即“你有我也有”的记录才会保留。
  - 通常无需显式写出 `how='inner'`。

- **左连接 `left`**
  - 设置 `how='left'`。
  - 以左表为基准进行匹配。
  - 类似常见的 `VLOOKUP` 思路：把右表匹配信息带到左表中。
  - 适用于从多张表、维度表或数据表中为一张主表补充字段。

- **右连接 `right`**
  - 设置 `how='right'`。
  - 以右表为基准进行匹配。
  - 左连接和右连接存在顺序问题：需要明确谁在左、谁在右，以及以哪张表为基准。

- **全外连接 `outer`**
  - 设置 `how='outer'`。
  - 保留两张表的所有部分。
  - 不是简单地把两张表“粘在一起”，而是按连接键整合所有记录。
  - 某一侧没有匹配数据时，对应位置显示为空值。
  - 可理解为左连接加右连接的组合结果。
  - 全外连接通常不存在左右表顺序影响连接范围的问题，但左右连接对顺序敏感。

`merge` 的连接语法可概括为：

`pd.merge(left, right, how='left', on=['k1', 'k2'])`

其中：

- 前面的表是左表。
- 后面的表是右表。
- `how` 指定连接方式。
- `on` 指定连接字段。

### suffixes 参数：处理同名字段

当左右表合并时，如果存在同名字段，例如两个表都有 `k`、`v` 这类完全相同的列名，合并后会产生重名列，难以区分来源。

此时可使用 `suffixes` 参数为同名列添加后缀：

`pd.merge(left, right, on='k', suffixes=('_l', '_r'))`

- 第一个后缀用于左表同名列。
- 第二个后缀用于右表同名列。
- 后缀字符可以自定义，只要写在引号中即可。
- 常用 `_l` 表示 left，`_r` 表示 right，也可按个人习惯设置。

该参数的作用是：当表与表合并出现同名字段时，明确区分哪个字段来自左表，哪个字段来自右表。

## 三、join 的用法与特点

### join 的基本定位

- `join` 语法简单，但功能相对有限。
- 课程中明确建议：实际使用中不建议优先使用 `join`。
- 原因不是它不能连接，而是过于简单，后期很多复杂场景下使用起来不方便。
- 因此本节课对 `join` 只做介绍和了解。

### join 的默认行为：按索引横向连接

基本语法：

`left.join(right)`

示例：

- 左表由字典创建，字段包括：
  - `姓名1`
  - `年龄一`
- 右表由字典创建，字段包括：
  - `姓名2`
  - `年龄二`
- 将两个字典分别放入 `DataFrame` 后，使用左表 `.join()` 右表。

`join` 默认表现为横向连接：

- 将右表的列横向拼接到左表右侧。
- 如果左右表索引相同，例如索引都是 `0,1,2,3`，则直接按索引横向拼接。
- 拼接后左表字段和右表字段并排显示。
- 如果索引不一致，某些位置没有对应数据，则结果中对应位置为空值。

因此，`join` 的一个关键点是：它主要依据索引进行对齐，而不是像 `merge` 那样默认通过 `on` 指定同名列。

### join 中指定 on 参数

`join` 也可以通过 `on` 指定匹配依据。

讲解示例中，右表的部分键信息位于索引中，例如 `k0`、`k1` 等索引。此时可以指定左表中的某列与右表索引进行匹配：

`left.join(right, on='k')`

其效果可理解为：

- 左表保留自身数据。
- 根据左表中指定的列，与右表索引进行匹配。
- 将右表中匹配到的数据带入左表对应位置。
- 属于 `k0` 的数据匹配到相应位置，属于 `k1` 的数据匹配到相应位置。
- 匹配结果表现为右表数据按匹配关系铺到左表中。
- 没有匹配到的位置显示为空值。

讲解中形容这种展开方式类似按索引/键把数据铺开。需要特别注意：`join` 的 `on` 语义与 `merge` 的 `on` 不完全相同，`join` 常涉及左表列与右表索引之间的匹配。

### join 连接多个 DataFrame

`join` 支持一次连接多个 `DataFrame`，可将需要连接的多张表放入列表中：

`left.join([right, right2])`

含义：

- 以左表为基础。
- 依次连接列表中的 `right` 和 `right2`。
- 最终得到多表横向连接后的结果。

示例中右表命名为 `right`、`right2`，左表为 `left`，通过列表形式传给 `join`，即可完成多个 `DataFrame` 的组合。

## 四、merge 与 join 的对比总结

| 对比项 | merge | join |
|---|---|---|
| 主要用途 | 灵活的数据合并 | 简单的横向连接 |
| 默认对齐方式 | 通过 `on` 指定同名列 | 默认按索引对齐 |
| 连接类型 | 支持 `inner`、`left`、`right`、`outer` | 功能较简单 |
| 多表连接 | 可通过多次 `merge` 或额外处理 | 可用列表一次连接多个 `DataFrame` |
| 推荐程度 | 常用、推荐掌握 | 了解即可，不建议优先使用 |
| 注意事项 | 注意同名列、连接字段、连接顺序 | 注意索引是否一致，索引不同会产生空值 |

## 五、关键结论

- `merge` 是 pandas 中更常用、更灵活的数据合并方式，应重点掌握。
- 使用 `merge` 时，优先明确三件事：
  - 用哪些列连接：`on`
  - 使用哪种连接方式：`how`
  - 同名列如何区分：`suffixes`
- 默认 `merge` 是内连接，只保留左右表都匹配的记录。
- 左连接、右连接要明确基准表；全外连接保留所有记录，不匹配处为空值。
- `join` 默认按索引横向连接，索引不一致时会产生空值。
- `join` 可通过 `on` 指定左表列与右表索引进行匹配，也可用列表连接多个 `DataFrame`。
- 实际项目中建议优先使用 `merge`，`join` 作为补充了解。
