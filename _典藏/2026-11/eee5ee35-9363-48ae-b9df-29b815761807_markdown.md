# 多层索引与多层索引计算（Pandas）

## 1. 课程主题与示例数据

本节主题是 **分层索引（MultiIndex）** 与 **分层索引计算**。核心内容包括：

- 如何把普通 DataFrame 设置成多层索引。
- 如何查询多层索引。
- 有序索引与无序索引的区别及处理方式。
- 多层索引的三种创建方式。
- 如何利用多层索引计算“总计/合计”，并与原表横向拼接。

### 1.1 导入库与读取 Excel

课程开始导入 `pandas`，并用 `read_excel` 读取 Excel 文档：

```python
import pandas as pd

data = pd.read_excel(path, sheet_name="有序")
```

说明：

- `sheet_name="有序"`：指定读取 Excel 中的“有序”工作表。
- 该 Excel 内有多个工作表，课程还使用了“无序”工作表做对比。

示例数据中：

- 第一层是班级：一班、二班、三班。
- 第二层是学号或姓名：a、b、c 等。
- 数据值是分数。

层级关系可以理解为：

- 班级管理学号；
- 学号管理分数；
- 分数由对应学生决定；
- 一层套一层，形成多层索引。

### 1.2 读取时直接设置多层索引

使用 `read_excel` 的 `index_col` 参数，把第 0 列和第 1 列设置为多层行索引：

```python
data = pd.read_excel(path, sheet_name="有序", index_col=[0, 1])
```

说明：

- `index_col=[0, 1]`：把第 0 列“班级”和第 1 列“学号”设置为行索引。
- 两层行索引形成 `MultiIndex`。
- 显示效果为：一班下有 a、b、c；二班下有 a、b、c 等。

### 1.3 另一种设置方式：set_index

大多数老师常用另一种写法：先正常读取，再用 `set_index` 设置索引：

```python
data = pd.read_excel(path, sheet_name="有序")
data = data.set_index(["班级", "学号"])
```

对比与结论：

- 方式一：读取时使用 `index_col=[0, 1]`。
- 方式二：先读取，再 `set_index(["班级", "学号"])`。
- 两种方式二选一即可，结果本质相同。
- 讲师个人习惯使用 `index_col`，因为少写一步。
- 有些老师习惯 `set_index`，两者没有绝对对错。

## 2. 什么是分层索引

分层索引，即 `MultiIndex`，是指一个行索引或列索引由多个层级组成。

例如：

- 外层索引：班级。
- 内层索引：学号。
- 数据值：分数。

可以理解为：

- 班级是第 1 层索引，也叫外层索引、一级索引。
- 学号是第 2 层索引，也叫内层索引、二级索引。
- 多层索引适合表达有层级关系的数据，如“班级 → 学号 → 分数”“科目 → 得分类型”“年 → 月”等。

与普通单层索引的区别：

- 普通索引一个行标签只有一个值。
- 多层索引一个行标签由多个值组成，例如 `("一班", "a")`。
- 查询时通常使用元组形式传入多个层级标签。

## 3. 分层索引查询：loc 的使用

查询多层索引主要使用 `loc`。

`loc` 的基本语法：

```python
data.loc[行标签, 列标签]
```

说明：

- 前面是行标签，后面是列标签。
- 列标签位置写 `:` 表示所有列。
- 多层索引查询行时，多个层级标签要用元组表示，例如 `("一班", "a")`。

### 3.1 查询某个外层索引下的所有行

例如查询“一班”下所有行、所有列：

```python
data.loc[("一班", slice(None)), :]
```

说明：

- `"一班"`：外层索引。
- `slice(None)`：表示内层索引选择任意标签，相当于“该层所有行”。
- `:`：表示所有列。
- 讲师也说明，实际写代码时列位置的 `, :` 可以省略，但讲解时写全，便于理解。

### 3.2 查询具体多层标签

查询“一班”中“a”的所有列：

```python
data.loc[("一班", "a"), :]
```

说明：

- 元组中第一个值是外标签。
- 第二个值是内标签。
- 后面 `:` 表示所有列。
- 如果查询多个索引标签，就继续在元组中按层级写下去。

### 3.3 重要易混点：行内层所有不能直接写冒号

- 表示所有列时，可以使用 `:`。
- 但在多层索引行标签的元组中，表示某一层“所有标签”时，不能直接写 `:`，而应使用：

```python
slice(None)
```

例如：

```python
data.loc[("一班", slice(None)), :]
```

结论：

- 列所有：用 `:`。
- 行内层所有：用 `slice(None)`。
- `slice(None)` 等价于 Python 切片中的“任意/全部”含义，但在 MultiIndex 的元组中必须显式写出来。

## 4. 有序索引与无序索引

### 4.1 有序索引

示例“有序”表：

- 外层：一班、二班、三班。
- 内层：a、b、c 等。

特点：

- 一班、二班、三班有自然顺序。
- a、b、c 也有自然顺序。
- 这种索引可以直接使用 `loc` 查询。

### 4.2 无序索引

示例“无序”表：

- 外层索引：科目，例如语文、数学。
- 内层索引：得分类型，例如最高分、最低分。
- 数据含义：语文最高分、语文最低分、数学最高分、数学最低分。
- 例如语文最高分 90、语文最低分 50；数学最高分 100、数学最低分 60。

这种索引没有自然排序关系，属于无序索引。

### 4.3 检查索引是否有序

可以使用：

```python
data.index.is_monotonic_increasing
```

说明：

- 返回 `True`：索引按升序有序。
- 返回 `False`：索引无序。
- 课程中“无序”表检查结果为无序。

### 4.4 无序索引的处理：先排序再查询

对于无序索引，直接查询可能报错。建议先排序：

```python
data = data.sort_index(level="科目")
```

说明：

- `sort_index`：按索引排序。
- `level="科目"`：指定按“科目”这一层索引排序。
- 排序后再查询，例如：

```python
data.loc["语文"]
```

结论：

- 有序索引可以直接查询。
- 无序索引建议先 `sort_index(level=...)` 排序，再查询。
- 并不是所有无序索引都会报错，但排序后查询更安全。
- 讲师强调：这一步要根据数据情况判断，但无序时排序是推荐做法。

## 5. 多层索引的创建方式

课程列出三种创建 `MultiIndex` 的方式。

### 5.1 方式一：from_arrays

`from_arrays` 接收多维数组来创建分层索引。课程中实际使用的是二维数组形式。

示例：

```python
多层 = pd.MultiIndex.from_arrays(
    [["a", "a", "b", "b"], [1, 2, 1, 2]],
    names=["x", "y"]
)
```

说明：

- 第一个列表 `["a", "a", "b", "b"]` 是外层索引。
- 第二个列表 `[1, 2, 1, 2]` 是内层索引。
- `names=["x", "y"]` 用于设置两层索引的名称。
- 输出效果：外层为 a、a、b、b，内层为 1、2、1、2。

结论：

- `from_arrays` 可以用数组形式创建多层索引。
- 讲师不推荐单独使用这种方式。

### 5.2 方式二：from_tuples

`from_tuples` 接收元组列表来创建多层索引。

示例：

```python
多层 = pd.MultiIndex.from_tuples(
    [("a", 1), ("a", 2), ("b", 1), ("b", 2)],
    names=["x", "y"]
)
```

说明：

- 每个元组表示一个多层索引标签。
- 小括号中左边是高维索引，也就是一级索引。
- 逗号后边是二级索引。
- `names=["x", "y"]` 设置层名。
- 结果与 `from_arrays` 类似。

结论：

- `from_tuples` 通过元组列表明确指定每一层的标签。
- 讲师同样不推荐作为首选方式。

### 5.3 方式三：from_product（推荐）

`from_product` 通过笛卡尔积创建多层索引，是讲师推荐的方式。

示例：

```python
多层 = pd.MultiIndex.from_product(
    [["a", "b"], [1, 2]],
    names=["x", "y"]
)
```

说明：

- 参数是嵌套的可迭代对象。
- 结果会让每个一维数组的元素和其他一维数组元素生成索引内容。
- 本质是生成笛卡尔积。
- 输出为：`("a", 1)`、`("a", 2)`、`("b", 1)`、`("b", 2)`。
- `names=["x", "y"]` 设置层名，也可以分开设置。

讲师说明：

- 如果对笛卡尔积不熟悉，可以看 Excel 基础篇、Excel Power Pivot 或 Power BI 基础相关内容。
- 推荐使用 `from_product`，因为它生成多层索引更方便。
- 索引名字既可以写在 `from_product` 里面，也可以后续设置。

### 5.4 行索引与列索引的创建

多层行索引和多层列索引的设置方法完全一样，只是变量名不同：

- 行索引变量通常叫 `index`。
- 列索引变量通常叫 `columns`。

示例：

```python
index = pd.MultiIndex.from_product(
    [[2023, 2024], [1, 2]],
    names=["年", "月"]
)

columns = pd.MultiIndex.from_product(
    [["香蕉", "苹果"], ["土豆", "茄子"]],
    names=["水果", "蔬菜"]
)

df = pd.DataFrame(
    np.random.rand(4, 4),
    index=index,
    columns=columns
)
```

说明：

- `index`：多层行索引。
- `columns`：多层列索引。
- `np.random.rand(4, 4)`：生成 4 行 4 列随机数据。
- `pd.DataFrame(..., index=index, columns=columns)`：用多层行索引和多层列索引创建 DataFrame。
- 行索引和列索引的设置方法没有区别，只是用于区分行和列。
- 相关语法可查看 pandas 笔记 3.2。

## 6. 分层索引计算案例：销售表总计

### 6.1 读取销售表并设置多层行列索引

课程使用 `销售.xlsx` 做案例。

先读取并打印：

```python
path = "销售.xlsx"
data = pd.read_excel(path)
print(data)
```

说明：

- Excel 中存在合并单元格。
- 读取后显示可能错位，但不影响后续数据处理。

默认情况下，第一行数据会被当作列索引。现在需要把两行都设置为列索引，把前两列设置为行索引：

```python
data = pd.read_excel(path, header=[0, 1], index_col=[0, 1])
```

参数说明：

- `header=[0, 1]`：指定 Excel 第 0 行和第 1 行作为列标签，形成多层列索引。
- `index_col=[0, 1]`：指定 Excel 第 0 列和第 1 列作为行索引，形成多层行索引。
- `header` 管列标签。
- `index_col` 管行标签。
- 这两个概念容易混，讲师提示可回看 pandas 笔记 2.1.2。

读取后列索引大致为：

- 土豆 → 销量、毛利。
- 倭瓜 → 销量、毛利。

即 `data.columns` 是两层列索引。

### 6.2 计算总计：表与表相加

目标：

- 土豆销量 + 倭瓜销量。
- 土豆毛利 + 倭瓜毛利。
- 生成“总计/合计”数据。

先验证单列相加：

```python
结果1 = data["土豆"]["销量"] + data["倭瓜"]["销量"]
```

说明：

- `data["土豆"]` 取出土豆这一组列。
- `data["土豆"]["销量"]` 取出土豆销量列。
- 同理取出倭瓜销量列。
- 两者相加得到销量合计。

再让两个子表直接相加：

```python
结果2 = data["土豆"] + data["倭瓜"]
```

说明：

- `data["土豆"]` 是一个二维子表。
- `data["倭瓜"]` 也是二维子表。
- 两个二维数据相加时，会按索引和列标签对齐。
- 因为两个子表的索引相同，所以可以逐项相加。
- 得到的结果包含“销量”和“毛利”两列。
- 但此时结果的列索引只有一层，还没有“合计”外层。

结论：

- 一行数据与另一行数据相加可以。
- 两个二维表相加也可以，但必须关注索引是否对齐。
- 上节课已经讲过算术运算和数据对齐问题。

### 6.3 给总计创建多层列索引

为了能和原表按相同层级横向拼接，需要把总计的列也变成多层索引。

先计算总计：

```python
总计 = data["土豆"] + data["倭瓜"]
```

此时 `总计.columns` 只有“销量”“毛利”等单层标签。使用 `from_product` 给它增加外层“合计”：

```python
总计.columns = pd.MultiIndex.from_product(
    [["合计"], 总计.columns]
)
```

说明：

- `["合计"]`：外层索引，表示合计。
- `总计.columns`：内层索引，即原来的销量、毛利。
- 外层“合计”必须放在列表中，写成 `["合计"]`。
- 第二个参数也作为可迭代对象传入。
- 生成的多层列索引为：`("合计", "销量")`、`("合计", "毛利")`。

关键注意点：

- `总计.columns` 赋值时不要忘记用列表把外层“合计”包起来。
- 这里的目的不是只改列名，而是制造和原表层级一致的多层列索引。
- 之前多表连接、数据合并与重塑中讲过：索引必须一致才能方便连接。此处同理，列索引层级要一致，才能进行拼接。

### 6.4 横向拼接原表与总计

使用 `pd.concat` 横向拼接：

```python
结果 = pd.concat([data, 总计], axis=1)
print(结果)
```

说明：

- `pd.concat([data, 总计], axis=1)`：按列方向横向拼接。
- `axis=1` 表示横向拼接。
- 如果忘记 `concat` 的用法，可回看笔记 4.3.3 横向拼接。
- 拼接后列结构为：
  - 土豆 → 销量、毛利
  - 倭瓜 → 销量、毛利
  - 合计 → 销量、毛利

最终结果：

- 土豆下有销售、毛利数据。
- 倭瓜下有销售、毛利数据。
- 合计下有销售、毛利数据。
- 课程中打印结果存在显示错位，但数据结构正确。

### 6.5 写回 Excel 与 PyCharm 显示错位问题

结果可以写回 Excel：

```python
结果.to_excel("输出.xlsx")
```

说明：

- 写回 Excel 一般没有问题。
- 但在 PyCharm 控制台中显示多层索引时，可能出现错位。
- 讲师说明这是 pandas/PyCharm 显示层面的错位问题，不影响最终数据结果。
- 目前讲师没有查到更好的解决方法，只能接受这种显示效果。

踩坑结论：

- 多层索引在 PyCharm 中打印可能错位。
- 错位不代表数据错误。
- 写回 Excel 后通常可以正常保存结构。
- 学习时重点检查列索引层级和数据对齐，而不是只看控制台对齐效果。

## 7. 常用函数与参数速查

## 8. 关键结论与踩坑清单

- 多层索引的本质是“一层管一层”，如班级管学号、学号管分数。
- 设置多层行索引有两种常见方式：
  - 读取时：`index_col=[0, 1]`。
  - 读取后：`set_index(["班级", "学号"])`。
- 两种方式二选一，讲师个人偏好 `index_col`，因为少一步。
- `loc` 查询多层索引时，行标签用元组表示，例如 `("一班", "a")`。
- 列所有可以用 `:`。
- 行内层所有不能直接写 `:`，要写 `slice(None)`。
- 有序索引可以直接查询。
- 无序索引建议先用 `sort_index(level="科目")` 排序，再查询。
- 检查索引是否有序用 `data.index.is_monotonic_increasing`。
- `MultiIndex` 创建方式有三种：
  - `from_arrays`：数组方式。
  - `from_tuples`：元组列表方式。
  - `from_product`：笛卡尔积方式，推荐。
- 行索引和多层列索引创建方法一致，只是变量名分别为 `index` 和 `columns`。
- 多层索引计算时，表与表相加会按索引和列标签对齐。
- 若两个子表索引相同，可以直接相加。
- 相加后若列索引只有一层，需要手动创建多层列索引。
- 给总计增加外层“合计”时，使用：
  ```python
  总计.columns = pd.MultiIndex.from_product([["合计"], 总计.columns])
  ```
- 外层“合计”必须用列表包起来，否则层级结构容易写错。
- 横向拼接使用 `pd.concat([data, 总计], axis=1)`。
- 拼接前要保证列索引层级一致，否则多层结构无法正确对齐。
- PyCharm 控制台显示多层索引可能错位，但不影响数据结果和写回 Excel。
- 讲师强调：不需要背下所有 pandas API；应先理解原理，再通过笔记查询。课程笔记附录中包含多层索引相关中文解释，包括 `levels`、`names` 等内容，使用时查阅即可。
