## 1. AI 与大模型基础

### 1.1 从 AI 到机器学习、深度学习、生成式 AI

- **AI，人工智能**：让机器完成原本需要人类智能才能完成的任务，例如识别图像、理解语言、下棋、驾驶。
- AI 学科起点：1956 年夏天的达特茅斯会议。
- 早期 AI 靠人写规则。例如判断垃圾邮件：
  - 出现“中奖”算垃圾邮件
  - 出现“汇款”也算垃圾邮件
  - 问题是规则永远写不完，对方换一种说法，规则就失效。
- **机器学习**：不再让人写规则，而是给机器大量带答案的例子，让它自己找规律。
  - 示例：给一万封已标注“是/不是”垃圾邮件的邮件，让模型学习。
  - 学完后，遇到没见过的新邮件也能判断。
- **深度学习**：机器学习里效果最好的一类方法，使用**神经网络**。
  - 神经网络由大量简单计算单元组成，一层连着一层。
  - 每一层从数据里提取一部分特征，层数越多，能学会的东西越复杂。
  - “深度”指的就是层数多。
  - 2012 年，**AlexNet** 深度神经网络在图像识别比赛中大幅领先，此后深度学习成为 AI 主流。
- **生成式 AI**：前面的 AI 大多在做判断，例如“这是不是猫”“这封邮件是不是垃圾邮件”；生成式 AI 能创造新内容，例如写文章、画图、作曲、做视频。
- **AIGC**：由 AI 生成的内容统称。
- **大模型**：生成式 AI 里最重要的一种，专门处理语言。
  - ChatGPT、DeepSeek、豆包、Kimi 背后都是大模型。

概念关系：

- AI 包含机器学习
- 机器学习包含深度学习
- 生成式 AI 建立在深度学习之上
- 大模型是生成式 AI 里最重要的一种

### 1.2 大模型 LLM 的核心原理

- 大模型全称是**大语言模型**，英文缩写 **LLM**。
- 核心能力只有一个：根据前面的文字，预测下一个字最可能是什么。
- 示例：输入“床前明月”，模型给所有可能的下一个字打分，“光”概率最高；选出“光”后，再基于“床前明月光”预测下一个字。
- 就这样一个接一个，生成一整段话。你在 AI 那里看到的每个回答，都是逐字生成的。
- 为什么能预测得准：训练时读过海量文字，从中学到了：
  - 语言的规律
  - 世界的知识
  - 一定的推理能力
- 为什么叫“大”：
  - 读过的文字多
  - 内部存储知识的参数多
- **温度（temperature）**：挑选下一个字时可调整的设置。
  - 温度低：模型几乎总选概率最高的字，回答稳定、保守，适合写代码、查资料。
  - 温度高：更多选择概率低一些的字，回答更有变化，也更容易出错，适合写故事、想创意。

### 1.3 模型与产品的区别

- **模型**：例如 GPT 是模型。
- **产品**：例如 ChatGPT 是基于 GPT 模型做的产品。
- DeepSeek App 里运行的是 DeepSeek 的模型；豆包 App 背后是字节的豆包大模型。
- 产品会在模型外面加上聊天界面、联网搜索、文件上传等功能。
- 同一个模型放在不同产品里，效果可能完全不同。

### 1.4 Token 与分词器

- **Token**：模型处理文字时用的最小单位，中文名叫**词元**。视频提到，这是全国科学技术名词审定委员会“今年 3 月”推荐的叫法。
- 一个 Token 不一定是一个字。
- 模型只能处理数字，所以文字进入模型前要先经过**分词器**：
  - 把文字切成一小块一小块
  - 每一块对应词表里的一个编号
  - 这一小块就是一个 Token
- 怎么切是从大量文字里统计出来的：
  - 经常一起出现的字会被合成一块
  - 常见词可能一块就够
  - 不常见的字可能要拆成好几块
  - 英文单词也经常被拆开
- 一个模型的词表里通常有十几万个这样的块。
- 一个汉字等于几个 Token 没有固定答案，每个模型的分词器都不一样。
- 按 DeepSeek 官方给出的换算：
  - $1$ 个中文字符 $\approx 0.6$ 个 Token
  - $1$ 个英文字符 $\approx 0.3$ 个 Token
- 这也解释了著名问题：`strawberry` 里有几个字母 `r`，为什么 AI 常常答错？
  - 因为在模型眼里，这个单词是几个 Token，而不是十个字母，它看不到单个字母。
- Token 之所以重要，是因为几乎所有东西都按它计算：
  - 价格：按每一百万个 Token 收费
  - 输入：你发给模型的内容
  - 输出：模型生成的内容，通常更贵
  - 速度：按每秒生成多少个 Token 计算
  - 上下文容量：模型一次能处理多少内容，也按 Token 计算

### 1.5 参数、训练、后训练与推理

- **参数**：也叫**权重**，是模型内部的大量数字，可以理解成一个个可调节的旋钮。模型学到的知识和能力都存在这些数字里。
- 模型名字后的 **7B、70B** 指参数数量：
  - B 代表十亿
  - 70B 就是 700 亿个参数
- **预训练**：训练的第一阶段。
  - 给模型一段文字，遮住下一个 Token，让它猜。
  - 猜完与正确答案对比，算出差距。
  - 把所有参数往“猜得更准”的方向稍微调整一点。
  - 这个过程重复成千上万亿次。
  - 示例：DeepSeek-V3 预训练读了 14.8 万亿个 Token 的文字。
- **基座模型**：预训练完成后得到的模型。
  - 很擅长续写，但还不会好好回答问题。
  - 你问“中国的首都是哪里”，它可能接着写“美国的首都是哪里”，因为训练文本里这类问题常成串出现。
- **后训练**：第二阶段。
  - **监督微调**：用大量人工写好的问答示范，教它该怎么回答。
  - **强化学习**：让它回答问题、给回答打分，按分数调整参数，使其更倾向给出好回答。
  - 打分如果来自人，就叫**人类反馈强化学习**，英文缩写 **RLHF**。
  - 经过后训练，基座模型才变成平时用的聊天助手。
  - DeepSeek 更新日志里写“仅重新进行了后训练”，指的就是这一步。
- **算力**：训练需要巨大计算量，要用成千上万张显卡连续计算好几个月。这也是 AI 公司抢购显卡的原因。
- **推理，inference**：训练完成后，你每发一次消息，模型就用训练好的参数计算一次并生成回答。
  - 训练是造模型
  - 推理是用模型

### 1.6 Transformer、注意力机制与权重文件

- **Transformer**：现在几乎所有大模型都在使用的模型结构，由谷歌在 2017 年的一篇论文里提出。
- 核心是**注意力机制**：
  - 预测下一个 Token 时，模型会回头看前面所有 Token。
  - 判断哪些和当前最相关，重点参考它们。
  - 示例：“小明把苹果给了小红，因为她饿了”，读到“她”时，注意力会集中在“小红”上。
- 训练好的参数保存在一组文件里，叫**权重文件**。

### 1.7 开源模型、开放权重、闭源模型与本地部署

- 有的公司会公开发布权重文件，任何人都能下载使用，这就是常说的**开源模型**。
- 示例：DeepSeek 的模型发布在 Hugging Face 上，一个模型的权重文件加起来有五百多 GB。
- DeepSeek 采用 MIT 许可，个人和公司都可以免费下载、修改和商用。
- 但各家许可证不一样，有的模型用自己写的许可证，商用要满足条件，下载前要看清楚。
- 严格来说，这更应该叫**开放权重**。
- 按照开放源代码促进会的定义，真正的开源 AI 还要公开训练数据的详细信息和训练代码，而大多数“开源模型”只公开了权重。
- 反过来，不公开权重、只能通过官方产品或接口使用的，叫**闭源模型**，例如 GPT、Claude、Gemini。
- **本地部署**：把模型放到自己的电脑上运行。
  - 优点：数据不离开电脑、不需要联网、不用按 Token 付费。
  - 常用工具：Ollama、LM Studio。
  - 能不能跑起来主要看显卡的显存。
  - 一个参数通常占 2 个字节，一个 70B 模型光权重就要约 $70B \times 2\text{ bytes} \approx 140GB$ 显存，普通电脑根本装不下。
  - 所以开源不等于你就能用得上。

### 1.8 让模型更便宜更快：MoE、蒸馏、量化

- **MoE，混合专家**：
  - 把模型内部拆成很多组小网络，每组叫一个专家，再加一个负责分配任务的路由器。
  - 每生成一个 Token，路由器只挑出最合适的几个专家来计算，其他专家不参与。
  - 这样模型总参数可以很大，但每次真正参与计算的参数很少，速度快、成本低。
  - 模型发布页常写两个数字：总参数和激活参数。
  - 示例：Kimi K3.1 Pro 总参数 2.8 万亿，每个 Token 只激活其中 1040 亿。
  - 注意：虽然每次只用一部分，全部参数仍然要加载进显存。
- **蒸馏**：
  - 用一个大模型去教一个小模型。
  - 先让大模型回答大量问题，再用这些问答训练小模型。
  - 小模型能学到大模型的一部分能力。
  - 大模型叫教师模型，小模型叫学生模型。
  - 示例：DeepSeek-R1 发布时，同时发布了多个蒸馏出来的小模型。
- **量化**：
  - 降低每个参数的精度。
  - 原本每个参数用 16 位存储；量化到 8 位，体积减半；量化到 4 位，只剩原来的四分之一。
  - 70B 模型量化到 4 位后，大约只需要 35GB。
  - 代价是精度降低，模型表现会下降一些。
  - 下载模型时看到的 Q4、Q8、FP8，标的就是量化的位数和格式。

## 2. 大模型的能力与错误

### 2.1 深度思考、思维链与推理模型

- **深度思考**：很多 AI 产品都有的功能。
  - 普通模型收到问题会直接生成答案。
  - 打开深度思考后，模型先生成一段思考过程：分析问题、拆解步骤、尝试解法、检查错误，最后才给出正式回答。
- **思维链**：这段思考过程叫思维链。
- **推理模型**：经过专门训练、擅长先思考再回答的模型。
  - 第一个主流推理模型是 OpenAI 在 2024 年 9 月发布的 o1。
  - 2025 年 1 月，DeepSeek-R1 发布并开放权重，让推理模型迅速普及。
- 术语区分：
  - **推理，reasoning**：指思考的过程。
  - **推理，inference**：指用模型计算一次、生成回答。
  - 两者中文都叫“推理”，但完全不同。
- 思考过程同样是 Token，同样要计算、要收费。
- 所以深度思考更慢、更贵，换来的是在数学、编程、复杂分析等问题上更准确。
- 很多模型能设置思考强度。DeepSeek 分为 low、high、max 三档：
  - 简单任务用 low
  - 日常 Agent 任务用 high
  - 更复杂任务用 max
- 简单问题不需要开深度思考；需要多步分析的问题再打开。
- 思考时间长，也不代表结论一定正确。

### 2.2 多模态与语音

- **模态**：文字、图片、声音、视频是信息的不同形式，在 AI 里叫不同的模态。
- **多模态模型**：能同时理解多种模态的模型。
- 图片怎么进入模型：
  - 图片被切成很多小方块。
  - 每个小方块转换成 Token，和文字 Token 放在一起处理。
  - 所以图片同样会占用 Token，图片越大占用越多。
- 有了多模态，可以让 AI 读出截图里的表格、看懂图表、分析视频里发生了什么。
- 声音方面：
  - **ASR，语音识别**：把声音转成文字，例如把会议录音转成文字稿。
  - **TTS，语音合成**：把文字转成声音，例如视频里的 AI 配音。

### 2.3 扩散模型与生成式图像视频

- AI 画图、做视频大多使用另一类模型：**扩散模型**。
- 原理：
  - 训练时，先拿一张清晰图片，一步一步加噪点，直到变成完全随机的雪花。
  - 然后让模型学习反过来的过程：如何从带噪点的图里一步步去噪，恢复原图。
  - 生成图片时，从一张纯噪点的图开始，让模型一步步去噪。
  - 你输入的文字描述会在每一步引导去噪方向，最后画面变成你描述的样子。
- 常见叫法：
  - 用文字生成图片：**文生图**
  - 用图片生成新的图片：**图生图**
  - 用文字生成视频：**文生视频**
  - 用图片生成视频：**图生视频**
- 工具示例：Midjourney、即梦、可灵。
- 在聊天助手里让它画图，通常也是后台调用了这类模型。
- **数字人**：用 AI 生成的虚拟人物，可以根据文字或声音生成对应的口型、表情和动作，对着镜头说话。
  - 常用于直播带货、新闻播报、课程讲解，代替真人出镜。

### 2.4 幻觉与知识截止

- **幻觉**：模型生成了看起来合理、实际上错误或编造的内容。
  - 例如编出不存在的书、不存在的论文、不存在的法律条文，而且说得非常肯定。
  - 原因在于工作方式：模型做的是预测最可能出现的下一个 Token，而不是查证事实。
  - 当它不知道答案时，不会停下来，而是继续生成一个看起来最像答案的内容。
- **知识截止**：
  - 模型知识来自训练数据，数据收集到哪一天，它就只知道那一天之前的事。
  - 这个日期叫知识截止日期。
  - 问它之后发生的事，它要么不知道，要么可能编。
- 所以涉及数据、医疗、法律、财务的内容，一定要让它给出处，并且自己核实。
- 要从根本上减少幻觉，就要把真实资料交给它，这引出提示词、上下文、RAG 等内容。

## 3. 如何与模型沟通

### 3.1 提示词 Prompt

- 你发给 AI 的内容叫**提示词**，英文 **Prompt**。
- 提示词写得好不好，直接决定回答质量。
- 一个好提示词通常讲清楚四件事：
  - **背景**：你是谁、为什么做这件事
  - **任务**：具体要它做什么
  - **要求**：有哪些限制条件
  - **格式**：结果以什么形式呈现
- 示例对比：
  - 只说“帮我起个视频标题”，得到的多半是空泛标题。
  - 换成：“我是一个 AI 教学频道，这期讲 AI 术语，观众是新手。请给我 5 个标题，每个不超过 15 个字，不要用夸张的词。”结果会具体得多。
- 如果再给一两个你喜欢的标题做例子，效果会更好，这叫**少样本提示**。
- 研究怎样写好提示词的方法，叫**提示词工程**。

### 3.2 系统提示词

- 除了你写的提示词，还有一段你看不到的提示词，叫**系统提示词**。
- 它由产品方写好，放在每次对话最前面，规定：
  - AI 的身份
  - 说话风格
  - 行为规则
  - 能使用哪些工具
- 同一个模型，换一段系统提示词，就能变成客服、翻译或编程助手。
- 很多产品也允许你写自己的系统提示词：
  - ChatGPT 的自定义指令
  - 编程工具里放在项目目录下的 `AGENTS.md` 文件
- 把每次都要强调的要求写进去，以后就不用重复。

### 3.3 上下文、上下文窗口、截断与压缩

- 模型本身没有任何记忆。
- 每次你发送新消息，产品都会把以下内容全部打包，重新发给模型：
  - 系统提示词
  - 之前所有对话
  - 你上传的文件
  - 这条新消息
- 模型每次都从头读一遍这一整段内容，再生成回答。
- 这一整段内容叫**上下文**。
- 模型一次能处理的上下文有上限，叫**上下文窗口**，同样用 Token 计算。
- 示例：DeepSeek 现在的模型是 1M，即一百万个 Token；按官方换算，大约是 160 多万个汉字。
- 对话越来越长、超出窗口时，产品通常有两种处理方式：
  - **截断**：直接丢掉最前面的内容
  - **压缩**：把前面的对话总结成一段摘要
- 不管哪一种，前面的细节都会丢失。这就是为什么聊久了，AI 会忘记你最开始提的要求。
- 还有一个容易忽略的问题：就算没有超出窗口，上下文越长，模型对中间部分的关注越弱。
  - 有研究验证：关键信息放在开头或结尾，模型最容易用上；放在中间，最容易被忽略。
- 实际使用建议：
  - 一个任务开一个对话
  - 对话太长了就开新对话，把关键信息带过去

### 3.4 缓存与缓存命中

- 每次都把整段内容重新发送，费用会越来越高，因为输入 Token 每一轮都在累积。
- 为降低成本，服务商会把前面没有变化的部分存起来，下一次直接复用，不再重新计算，这叫**缓存**。
- 复用成功叫**缓存命中**，价格会便宜很多。
- 示例：DeepSeek 的 Flash 模型，缓存命中的输入价格只有未命中的五十分之一。
- 所以和 AI 长时间协作时，尽量不要改动前面的内容，例如中途修改系统提示词，否则缓存会失效。

### 3.5 记忆

- 模型本身没有记忆，但很多 AI 产品有“记忆”功能。
- **记忆是产品层面的功能**：
  - 产品会从对话里提取值得长期保留的信息，例如职业、偏好、经常提的要求。
  - 单独保存起来。
  - 新对话开始时，产品再把这些信息自动放进上下文开头。
- 要分清：
  - **上下文**：当前这次对话里模型能看到的内容，对话结束就没有了。
  - **记忆**：产品帮你保存、可以跨对话使用的信息。
  - 模型本身始终不记得任何事。

### 3.6 RAG、Embedding 与向量数据库

- 如果想让 AI 准确回答公司的规章制度、产品手册、你自己的笔记等它从未学过的内容，最常用的方法叫 **RAG**，中文是**检索增强生成**。
- RAG 分三步：
  - **准备资料**：把所有文档切成一段一段的小片段，存进资料库，这个资料库通常叫**知识库**。
  - **检索**：你提问时，系统先从知识库里找出和问题最相关的几段。
  - **生成**：把找到的片段和你的问题一起放进上下文，让模型根据这些资料回答。
- RAG 的三个优点：
  - 回答有依据，可以标出出处
  - 不需要重新训练模型
  - 资料更新后马上生效
- 联网搜索原理类似，只不过资料来源换成了互联网。
- RAG 的关键在检索：怎么找到最相关的片段？
  - 如果只按关键词匹配，你问“出差的钱怎么报”，可能找不到标题是“差旅费用报销流程”的文档，因为两句话用词不一样。
- 解决办法叫 **Embedding**，中文是**向量化**：
  - 用一个专门模型，把每一段文字转换成一长串数字，例如一千多个数字。
  - 这串数字叫**向量**。
  - 转换规则是：意思越接近的两段话，它们的向量越接近。
  - 这样系统就能按意思查找，而不只是按字面。
- 专门存储这些向量、并能快速找出最接近向量的数据库，叫**向量数据库**。
- 完整流程：
  - 文档切成片段
  - 片段转成向量
  - 存进向量数据库
  - 提问时，问题也转成向量
  - 找出最接近的几段
  - 交给模型生成答案

### 3.7 微调与 LoRA

- **微调**：在一个已经训练好的模型基础上，用你准备的数据再训练一轮，调整它的参数。
  - 示例：你有一千份合同，都按固定格式提取过信息，用它们来微调，模型就能稳定地按这个格式输出。
- 完整微调要调整全部参数，成本很高。
- 现在更常用的是 **LoRA**：
  - 原来的参数不动
  - 只额外训练一小部分新参数
  - 成本低得多
  - 很多 AI 绘画里的风格模型，就是用 LoRA 训练出来的
- RAG 和微调的区别：
  - RAG 是给模型一份随时可以翻阅的参考资料，模型本身没有变化。
  - 微调是让模型通过训练掌握一项新技能，改变的是模型本身。
- 选择建议：
  - 要让它知道新的知识，优先用 RAG。
  - 要让它学会一种固定格式、风格或专门技能，再考虑微调。
- 实际做项目时，一般先优化提示词，再试 RAG，最后才考虑微调。

## 4. 让 AI 替你干活

### 4.1 API、API Key 与 API 中转站

- **API**：中文是应用程序编程接口，是软件和软件之间互相调用的通道。
- 示例：开发一个记账小程序，希望拍一张小票就能自动识别金额和商品。
  - 你的程序通过 API 把小票图片和要求发给模型。
  - 模型把识别结果发回来。
  - 整个过程由程序自动完成。
- 通过 API 调用模型需要 **API Key**，即密钥，用来识别身份和计费，相当于账号密码，不能泄露。
- 费用按实际使用的 Token 计算，用多少付多少。
- 三种使用方式要分清：
  - 网页版和 App：给人直接使用的产品
  - 会员订阅：按月付费，在产品里使用
  - API：给程序调用的接口，按用量付费
- 在 Codex、Claude Code 等编程工具里接入 DeepSeek，走的就是 API。
- **API 中转站**：第三方把官方 API 转卖给你，价格通常更低。
  - 风险：你无法确认它背后调用的到底是不是你选的模型。
  - 你发送的所有内容都会经过它的服务器。

### 4.2 工具调用 Tool Calling

- 模型本身只能输出文字，不能上网、不能读取你的文件、不能操作任何软件。
- AI 能完成搜索、计算、查数据，靠的是**工具调用**。
- 整个过程分三步：
  - 程序把可以使用的工具告诉模型：每个工具叫什么名字、能做什么、需要填哪些参数。例如搜索工具的参数就是要搜索的关键词。
  - 当模型判断需要用工具时，它不会直接回答，而是输出一段固定格式的文字，写明要调用哪个工具、参数填什么。例如：调用搜索，关键词是“明天杭州天气”。
  - 程序读到这段文字，真正去执行搜索，再把搜索结果放回上下文。模型读到结果，接着生成最终回答。
- 这个机制叫**工具调用**，英文 **Tool Calling**。
- 最早由 OpenAI 在 2023 年 6 月推出，当时叫 **Function Calling**。
- 要记住：决定用什么工具、怎么用的是模型；真正去执行的是模型外面的程序。

### 4.3 工作流

- 一个稍微复杂的任务往往需要多次调用工具，这些步骤怎么安排？
- **工作流**：由人提前设计好的固定流程。
  - 第一步做什么、第二步做什么
  - 每一步调用哪个工具、用哪个模型
  - 都事先规定好
- 示例：每天早上 8 点自动抓取行业新闻，用 AI 生成摘要，整理成表格，发送到工作群。
- n8n、Dify 这类工具就是用来搭建工作流的：把一个个步骤像积木一样拖出来，连成一条线。
- 优点：稳定、可控、成本低，适合每次都一样的重复任务。
- 缺点：不够灵活，遇到流程之外的情况不会自己想办法。

### 4.4 Agent 智能体

- 如果任务每次都不一样，没法提前规定步骤，就需要 **Agent**，中文叫**智能体**。
- Agent 的核心是一个循环：
  - 先思考下一步该做什么
  - 然后调用工具去执行
  - 观察执行结果
  - 再根据结果决定下一步
  - 一直重复，直到完成任务
- 工作流的步骤是人定的，Agent 的步骤是模型自己定的。
- 示例：对 Agent 说“把我最近三期视频的数据整理成一份周报，存到 Notion 里”。
  - 它会先调用工具读取数据
  - 发现只拿到了两期，就再读一次
  - 数据齐了以后，计算每期的播放量和收藏率
  - 写好周报，调用工具存进 Notion
  - 最后检查页面有没有保存成功，才告诉我完成了
  - 每一步做什么，都是它自己决定的
- Agent 和普通聊天的区别：
  - 聊天：你问一句、它答一句
  - Agent：你给它一个目标，它自己规划步骤、使用工具、检查结果，直到把事情做完
- 常见 Agent：Codex、Claude Code、DeepSeek Harness、OpenClaw（被叫作“养龙虾”的）。
- 注意：智能体指的是能够自主完成任务的 AI 系统，和数字人、机器人不是一回事。

### 4.5 Harness

- Agent 执行任务时要处理很多事情：
  - 组织上下文
  - 提供工具清单
  - 真正执行工具调用
  - 判断任务是否完成
  - 上下文太长时进行压缩
  - 遇到删除文件这类危险操作时先征求你的同意
- 这些事情由包在模型外面的一整套程序完成，模型只负责思考和做决定。
- 这套程序叫 **Harness**。
- Harness 原意是马具：模型是马，Harness 是让这匹马能够干活的全套装备。
- 因此有一个简单公式：$Agent = 模型 + Harness$。
- Claude Code 的官方术语表就是这样定义的：Claude Code 是 Harness，Claude 是里面的模型。
- DeepSeek Harness 是 DeepSeek 推出的一套 Harness，本身不是模型，里面接入的是 DeepSeek 的模型。
- 同一个模型配上不同的 Harness，完成任务的能力可能差别很大，所以厂商公布 Agent 相关成绩时都会注明用的是哪个 Harness。
- 你在别处看到的 Agent 框架、Agent 平台，指的基本都是这一层。
- 围绕 Harness 的设计和优化，现在有了专门说法：**Harness 工程**。

### 4.6 MCP

- Harness 要给模型提供各种工具：读写文件、搜索网页、操作 Notion、查询数据库。
- 问题是每个软件的接入方式都不一样，每个 Harness 想接一个软件都要单独开发一次。
- **MCP** 就是为了解决这个问题的统一标准，全称是**模型上下文协议**，由 Anthropic 在 2024 年 11 月开源。
- 它规定了 AI 应用和外部工具之间统一的连接方式：
  - 软件方按照 MCP 做一个服务，叫 **MCP 服务器**
  - 所有支持 MCP 的 AI 应用都可以直接连接它，使用它提供的工具
- 我们常说的“安装一个 MCP”，实际上是让你的 AI 连接上一个 MCP 服务器。
- 前面例子里把周报存进 Notion，用的就是 Notion 官方的 MCP 服务器。
- MCP 和 API 的区别：
  - API 是某一个软件对外开放的接口，每家的格式都不一样
  - MCP 统一了 AI 连接这些接口的方式，相当于给 AI 和各种工具之间定了一个通用的插口标准

### 4.7 Skill

- 工具接上以后，还有一个问题：做事的具体方法。
  - 例如周报要包含哪几项、收藏率怎么计算、存到 Notion 的哪个页面。
  - 如果每次都在提示词里重新交代，既麻烦，又占用上下文。
- **Skill**，中文叫**技能**，就是把一项任务的完整做法打包成一个文件夹。
  - 里面有一份叫 `SKILL.md` 的说明文件，写清楚这项任务怎么做。
  - 还可以附上模板、参考资料，以及可以直接运行的脚本。
- Skill 由 Anthropic 在 2025 年 10 月推出，现在已经是开放标准，很多 Agent 都支持。
- Skill 最关键的设计叫**渐进式加载**：
  - 平时上下文里只放每个 Skill 的名字和一句简介，几十个 Skill 也只占很少 Token。
  - 只有任务需要用到某个 Skill 时，Agent 才把它的完整说明读进上下文。
- 几个容易混淆的概念对比：
  - **提示词**：你当前这一次的指令
  - **系统提示词**：每次对话都在，规定基本规则
  - **MCP**：负责连接外部工具，让 AI 能做事
  - **Skill**：提供做事的方法，让 AI 按你的标准做事，并且用到时才加载
- 一些产品里的插件，通常是把多个 Skill 和 MCP 打包在一起，方便一键安装。

### 4.8 子代理、多智能体与 A2A

- 任务越复杂，上下文就越长；上下文太长，模型表现会下降。
- 对大任务，常用解决办法叫**子代理**：
  - 主 Agent 把大任务拆成几个子任务，分别交给子代理处理。
  - 每个子代理都有自己独立的上下文。
  - 处理完以后，只把结论交回给主 Agent。
  - 示例：分析三期视频的数据，可以派三个子代理各看一期，主 Agent 只需要汇总三份结论，自己的上下文就不会被塞满。
- 多个 Agent 分工合作完成任务，叫**多智能体**。
- Agent 之间也需要统一的沟通方式。谷歌在 2025 年 4 月发布了 **A2A 协议**，专门用于 Agent 和 Agent 之间的通信。
- 可以这样区分：
  - MCP 连接 Agent 和工具
  - A2A 连接 Agent 和 Agent

### 4.9 上下文工程

- 系统提示词、记忆、RAG、Skill、工具结果、子代理，本质上都在解决同一个问题：
  - 在有限的上下文窗口里，放进最有用的信息。
- 这项工作现在有一个专门名字：**上下文工程**。
- 从提示词工程，到上下文工程，再到 Harness 工程，关注的范围一步步扩大。

### 4.10 Vibe Coding

- 当模型、Harness、工具、Skill 都具备以后，写程序这件事也发生了变化。
- 现在，不懂编程的人也可以用自然语言描述想要的功能，让 Agent 编写代码、运行、修改，自己只看结果、提意见。
- 这种编程方式叫 **Vibe Coding**，中文常叫**氛围编程**。
- 这个词由 OpenAI 创始成员 Andrej Karpathy 在 2025 年 2 月提出，后来被柯林斯词典选为 2025 年度词汇。
- 它大大降低了做软件的门槛，但要做出稳定可靠的产品，仍然需要懂代码的人来把关。

## 5. 评价模型与未来概念

### 5.1 Benchmark 与 SOTA

- **Benchmark**：基准测试，是一套固定的测试题。用同样的题考不同的模型，得到的分数就是常说的**跑分**。
- 不同基准测试考不同能力：
  - 有的考数学和推理
  - 有的考编程，例如 **SWE-bench**，让模型修复真实代码仓库里的问题
  - 有的考综合知识，例如被称为“人类最后的考试”的 **HLE**
- 某一项测试上目前的最高成绩叫 **SOTA**，意思是当前最佳。
- 看跑分要注意三点：
  - 第一，看是谁测的：官方自测和第三方评测结果可能不一样。
  - 第二，看测试条件：例如 DeepSeek 在更新日志里注明，Terminal-Bench 4.0 是用 Claude Code 作为 Harness 测出来的，换一个 Harness，分数就可能不同。
  - 第三，看有没有**数据污染**：如果测试题提前出现在训练数据里，模型相当于提前看过答案，分数会虚高。

### 5.2 AGI、ASI、具身智能与世界模型

- **AGI，通用人工智能**：
  - 指在大多数领域都能达到甚至超过人类水平、能自主学习和适应新任务的 AI。
  - OpenAI 在章程里把 AGI 描述为：在大多数具有经济价值的工作上超越人类的高度自主系统。
  - 目前还没有公认已经实现的 AGI，判断标准也存在争议。
- **ASI，超级人工智能**：
  - 指在几乎所有方面都远超人类的智能。
- **具身智能**：
  - 让 AI 拥有一个身体，能在真实世界里感知环境、移动、操作物体。
  - 人形机器人、自动驾驶汽车都属于具身智能的方向。
- **世界模型**：
  - 让 AI 理解物理世界的运行规律，能够预测接下来会发生什么。
  - 示例：谷歌在 2026 年 10 月底发布的 Genie 4，就是一个能生成可交互虚拟世界的世界模型，目前还处在研究预览阶段。
  - 世界模型被认为是具身智能的重要基础：机器人要在真实世界里行动，先要能预测自己的动作会带来什么结果。

## 6. 全局串联：一张概念地图

- AI 是最大的概念，往里是机器学习、深度学习、生成式 AI，大模型是其中最重要的一种。
- 大模型通过预训练和后训练，学会预测下一个 Token，知识存在参数里。
- 参数公开就是开放权重，可以本地部署。
- MoE、蒸馏、量化让它更便宜、更快。
- 大模型可以先思考再回答，可以理解多种模态，扩散模型负责生成图像和视频；它也会产生幻觉。
- 你和它沟通的所有内容——提示词、系统提示词、记忆、RAG 找来的资料——都放在上下文里，受上下文窗口限制。
- 通过 API，程序可以调用模型。
- 通过工具调用，模型可以操作外部工具。
- 工作流由人编排步骤，Agent 由模型自己决定步骤。
- Agent 等于模型加 Harness；MCP 连接工具，Skill 提供方法，子代理分担任务。
- 五十多个词，最后可以归成一张图。

## 7. 实战：读懂一段“术语很多”的更新日志

视频用 DeepSeek 官方更新日志 10 月 17 日的一条内容做检验，逐句解读：

- “官方网页端与 APP 模型也已同步更新”
  - 网页和 App 是产品，里面换上了新的模型。
- “API 调用方式与价格保持不变”
  - 给程序用的接口照旧，还是按 Token 计费。
- 下面一长串分数
  - 是基准测试的跑分。
- “Terminal-Bench 4.0，使用 Claude Code 框架测试”
  - Terminal-Bench 考的是 Agent 在终端里完成任务的能力。
  - 这个分数是 DeepSeek 的模型在 Claude Code 里跑出来的。
  - Claude Code 就是这里的 Harness。
- “缩短了模型的任务运行时间与输出长度”
  - 输出的 Token 少了，就更快、更便宜。
- “针对 DeepSeek Harness、腾讯 CodeBuddy、WorkBuddy 等平台框架进行了优化”
  - 同一个模型放进不同的 Harness，表现不一样，所以要专门适配。
- “具备原生多模态视觉理解能力”
  - 它能直接看懂图片。
- “推理速度更快”
  - 这里的推理是 inference，指用模型算一次的速度。

一页看起来像天书的更新日志，学完后每一句都能读懂。

## 8. 遇到 AI 新词时的判断方法

AI 新词每个月都在冒出来，但几乎都能放进这张概念图，而且只会落在三个地方：

- **模型本身**：让它更强、更便宜，例如训练、量化。
- **上下文里**：决定给它看什么，例如提示词、RAG。
- **模型外面**：给它配上手脚，例如工具调用、MCP、Harness。

下次再看到一个新词，先问自己两个问题：

- 它在这张图的哪一层？
- 它解决的是什么问题？

想清楚这两点，这个词就真正懂了。视频还提到，总图和每个词的一句话解释被整理成速查表，放在简介和博客里，方便以后遇到不懂的词回来查。
