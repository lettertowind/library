## 二、`merge` 参数总结

### 2.1 `merge` 的基本作用

- `merge` 用于两张表之间的连接查询，类似 SQL 中的连接。
- 基本调用形式：`pd.merge(left, right, on=..., how=..., suffixes=...)`。
- `left`：左表。
- `right`：右表。
- `on`：指定用于对齐、连接的列名。
- `how`：指定连接类型。
- `suffixes`：处理合并后同名列冲突的后缀参数。
- 使用 `on` 时必须保证左表和右表存在相同的列名。

### 2.2 `on` 参数：指定合并列的对齐

讲师示例表结构：

- 左表 `left`：索引为 `0,1,2,3`，字段为 `a, b, k1, k2`。
- 右表 `right`：索引为 `0,1,2,3`，字段为 `c, d, k1, k2`。
- 两表共同字段是 `k1`、`k2`，因此可以用 `k1`、`k2` 进行连接。

示例调用：

- `pd.merge(left, right, on=['k1', 'k2'])`

说明：

- `on` 用来指定连接列，类似 Excel 中 VLOOKUP 需要找到两表都有的同名字段。
- 这里用 `k1`、`k2` 把左表和右表进行合并。
- `on` 的核心是“对齐列名”，不是随便指定字段；必须确保左右表都有该列名。

### 2.3 `how` 参数：连接类型

未指定 `how` 时，`merge` 默认执行内连接：

- 默认值相当于 `how='inner'`。
- 内连接含义：左表和右表“你有我也有”的相交部分才保留。
- 讲师表述：内连接就是将两个表中相交的部分进行连接。

左连接：

- 通过 `how='left'` 指定。
- 以左表为基准进行连接。
- 类似常说的 VLOOKUP：从多张表或多重表中，为一张单表取回需要的字段。
- 左表、右表是一维表、维度表或数据表都可以进行这种连接。

右连接：

- 通过 `how='right'` 指定。
- 以右表为基准进行连接。
- 左连接和右连接存在顺序问题：谁在左、谁在右必须搞清楚；左连接以左表为基准，右连接以右表为基准。

全外连接：

- 对应 `how='outer'`。
- 将两张表所有部分都放到结果中，但不是简单把表拼接在一起，而是按连接键进行匹配。
- 某一侧没有匹配数据时，对应位置显示为空。
- 全外连接与 MySQL 中的全外连接含义一致。
- 全外连接可以理解为“左连接 + 右连接”，把左连接结果和右连接结果合在一起。
- 全外连接不存在左连接、右连接那种左右顺序基准问题。

### 2.4 `suffixes` 后缀参数

- `suffixes` 是上节课未讲、本节课补充说明的参数。
- 使用场景：两张表合并时，除连接列外还存在同名字段。例如两表都有 `v` 列，合并后会出现两个 `v`，无法区分哪个 `v` 来自哪张表。
- 通过 `suffixes` 给左右表同名列添加不同后缀，便于区分。
- 示例写法：`pd.merge(left, right, on=..., suffixes=('_l', '_r'))`。
- `_l` 表示左侧，`_r` 表示右侧。
- 后缀字符可以按自己的习惯任意指定，只要写在引号中即可。

### 2.5 `merge` 小结

- `merge` 是功能完整、参数较丰富的连接方式。
- 重点掌握：`on` 指定连接列；`how` 指定连接类型；`suffixes` 处理同名列冲突。
- 左连接、右连接要明确基准表；全外连接无左右基准问题。
- 若对上述连接概念不熟悉，说明 SQL 基础不足；需要先理解内连接、左连接、右连接、全外连接。

## 三、`join` 的使用与限制

### 3.1 讲师对 `join` 的定位

- 本节课对 `join` 只做介绍，不建议实际开发中优先使用。
- 原因：`join` 太简单，后期很多场景运用起来非常不方便。
- `join` 的核心行为是横向连接。

### 3.2 简单示例：按索引横向连接

讲师现场定义两个字典并转换为 `DataFrame`：

- 左字典：字段为 `姓名1`、`年龄1`；姓名为 `叶问`、`李小龙`、`孙兴华`；年龄为 `127`、`80`、`20`。
- 右字典：字段为 `姓名2`、`年龄2`；姓名为 `大刀王五`、`霍元甲`、`陈真`；年龄为 `176`、`152`、`128`。
- 将左字典、右字典分别放入 `DataFrame`，并分别写成两个变量，避免放在一起显得乱。

示例表达式：

- `left = pd.DataFrame(left_dict)`
- `right = pd.DataFrame(right_dict)`
- `print(left.join(right))`

结果说明：

- `left.join(right)` 直接完成两个表之间的连接。
- 该连接是横向连接，把右表横向放到左表旁边。
- 因为示例中三个索引相同，所以直接按索引横向拼接。
- 如果索引不一样，没有匹配位置的地方显示为空。

### 3.3 带 `on` 参数的 `join` 示例

讲师进一步用更直观的表说明：

- 左表索引为 `0,1,2,3`，包含 `a` 列、`b` 列和 `key` 相关列。
- 右表索引为 `k0`、`k1`，包含 `c` 列、`d` 列。
- 使用 `left.join(right, on='k')` 这类写法，通过 `on` 指定用于对齐的列。
- 该示例中，右表通过索引与左表的 `k` 列进行匹配，把属于 `k0` 的右表数据放到对应位置，把属于 `k1` 的右表数据放到对应位置。
- 最终效果是把右表数据按匹配关系横向拼接到左表上。

需要区分：

- `join` 默认更偏向按索引进行横向对齐。
- `merge` 的 `on` 是直接指定两张表共有的连接列名，连接语义更接近 SQL。
- `join` 的 `on` 用于指定对齐依据，使用时需要看清索引和列的关系。

### 3.4 一次组合多个 `DataFrame`

- `join` 可以一次组合多个 `DataFrame`。
- 示例：左表连接右表和右表二，可写成 `left.join([right, right2])`。
- 需要连接的多张表放在一个列表中。
- 讲师现场用 `left` 连接 `right` 和 `right2`，最终得到多表连接后的结果。

## 四、本课结论

- pandas 中的连接查询对应“数据合并与重塑”。
- `merge` 是主要连接工具，支持 `on`、`how`、`suffixes` 等参数，适合处理内连接、左连接、右连接、全外连接和同名列冲突。
- `merge` 未指定 `how` 时默认内连接；内连接只保留两表匹配相交部分。
- 左连接以左表为基准，右连接以右表为基准；全外连接相当于左连接加右连接。
- `join` 本质上是横向连接，默认按索引对齐；索引不一致时无匹配位置为空。
- `join` 可以通过 `on` 指定对齐依据，也可以通过列表一次连接多个 `DataFrame`。
- 讲师明确建议：`join` 只做了解，不建议依赖；复杂连接应优先使用更完整的 `merge`。
