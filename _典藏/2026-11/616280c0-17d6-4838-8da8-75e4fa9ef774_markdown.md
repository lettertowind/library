## 1. 连接查询的基本概念与 merge 的定位

- `merge` 的操作非常类似于 SQL 中的 `join`。
- 实际连接对象是两个表，也就是两个 `DataFrame`。
- 连接方式是“根据一些共有的列”把两个 `DataFrame` 连接起来。
- `concat` 相当于把两个表合并在一起；`merge` 更偏向于按共有列进行连接查询。
- 内连接可以类比 Excel 的 `VLOOKUP`。
- 实际场景中，共有列一般是 `id`、索引、序号等字段。
- 连接方式很多，`merge` 默认使用内连接。
- 默认内连接的含义：你也有、我也有，即两个表在连接键上相交的部分。
- 除内连接外，还有左连接、右连接、全外连接等。

讲师给出的 SQL 连接概念对应关系：

- 内连接：两个表之间相交的部分。
- 左连接：以左表为标准，左表有，同时把右表与左表重合的地方也包括进来。
- 右连接：与左连接相反，以右表为标准。
- 全外连接：两个表的内容都包括，相当于两个表的联合。

## 3. 默认内连接与显式 inner 写法

### 3.1 默认 merge

使用 `pd.merge` 把两个数据表连接起来：

- `数据三 = pd.merge(数据一, 数据二)`
- `print(数据三)`

由于两个表有共同的列 `姓名`，`merge` 默认按该列进行内连接。

默认内连接的结果特点：

- 只保留两个表中都存在的姓名。
- 数据一中有叶问、李小龙、孙兴华、李小龙、叶问、叶问。
- 数据二中有黄飞鸿、孙兴华、李小龙。
- 两边都有的姓名是李小龙和孙兴华。
- 叶问只存在于左表，黄飞鸿只存在于右表，因此默认内连接中不出现。
- 数据一中李小龙出现两次，数据二中李小龙出现一次。
- 连接结果中李小龙会出现两次，并且两行都带出数据二中李小龙的 `出手次数二`，即两行都显示为 3。
- 孙兴华在左表出手次数一为 2，在右表出手次数二为 2，因此结果中孙兴华带出两列次数。
- 这说明内连接取的是两个表按姓名相交的部分。

讲师解释“二表里有两个三次”的含义时，强调：左表中有两个李小龙，右表中李小龙对应一个值，匹配后右表的值会在结果中重复出现。

### 3.2 显式写出 on 与 how

内连接也可以写全：

- `pd.merge(数据一, 数据二, on='姓名', how='inner')`

参数含义：

- `on='姓名'`：指定用 `姓名` 字段进行连接。
- `how='inner'`：指定连接方式为内连接。
- `how` 是关键字参数，用来指定连接方式。
- `on` 是关键字参数，用来指定连接字段。

讲师运行后说明：显式写 `on='姓名', how='inner'` 的结果与默认 `pd.merge(数据一, 数据二)` 一样。

结论：

- 默认连接方式是内连接。
- 当两个表使用同名共有列进行连接，且连接方式为内连接时，`on` 和 `how='inner'` 可以省略。
- 但其他连接方式不能省略，必须显式指定 `how`。

## 4. 左连接、右连接、全外连接

### 4.1 左连接 left

将 `how` 改为 `left`：

- `pd.merge(数据一, 数据二, on='姓名', how='left')`

左连接含义：

- 谁在左边，就以谁为标准。
- 左表数据一的所有姓名都保留。
- 右表数据二中与左表匹配的数据被带出来。
- 右表中没有的姓名，对应列显示为空值 `NaN`。
- 左连接类似 Excel 的 `VLOOKUP`。

在示例中：

- 左表数据一有叶问、李小龙、孙兴华、李小龙、叶问、叶问。
- 左连接后左表所有行都保留。
- 叶问在右表中没有数据，因此对应 `出手次数二` 显示为 `NaN`。
- 李小龙和孙兴华在右表中有数据，因此把 `出手次数二` 带出来。
- 左表中李小龙有两行，右表中李小龙有对应值，所以两行李小龙都会带出右表的值。
- 讲师概括：左表是多端，从右表一端把数据 `VLOOKUP` 过来。

### 4.2 右连接 right

将 `how` 改为 `right`：

- `pd.merge(数据一, 数据二, on='姓名', how='right')`

右连接含义：

- 以右边表为基准。
- 右表数据二的所有姓名都保留。
- 右表示例中为黄飞鸿、孙兴华、李小龙。
- 用右表为基准，把左表数据一带过来。
- 左表中没有的姓名，对应列显示为 `NaN`。
- 黄飞鸿只存在于右表，左表中没有，因此左表列 `出手次数一` 显示为 `NaN`。
- 孙兴华、李小龙在左表中有匹配，因此带出 `出手次数一`。

讲师强调：左连接和右连接的区别就是“以哪边为基准”。

### 4.3 全外连接 outer

将 `how` 改为 `outer`：

- `pd.merge(数据一, 数据二, on='姓名', how='outer')`

全外连接含义：

- 两个表的内容都保留。
- 先保留左表叶问、李小龙、孙兴华、李小龙、叶问、叶问等所有行。
- 再把右表中存在、但左表中没有的黄飞鸿也带出来。
- 黄飞鸿在左表中无匹配，因此左表列显示为 `NaN`。
- 叶问在右表中无匹配，因此右表列显示为 `NaN`。
- 讲师概括：全外连接相当于两张表的联合。

## 5. 基于多个键的 merge 连接

### 5.1 多键连接概念

有时不能只按一个字段连接，而要按多个字段共同确定匹配关系。

- 例如：不仅按姓名，还要按班级共同匹配。
- 单键连接时写 `on='姓名'`。
- 多键连接时写 `on=['姓名', '班级']`。
- 多键连接就是把多个字段名放进一个列表里。
- 默认仍然是内连接；不写 `how` 时默认内连接。

### 5.2 多键连接示例数据

数据一示例：

- 姓名：张三、张三、王五。
- 班级：一班、二班、一班。
- 分数：10、20、30。

代码整理：

- `数据一 = pd.DataFrame({`
- `'姓名': ['张三', '张三', '王五'],`
- `'班级': ['一班', '二班', '一班'],`
- `'分数': [10, 20, 30]`
- `})`

数据二示例：

- 姓名：张三、张三、王五、王五。
- 班级：一班、一班、一班、二班。
- 分数：40、50、60、70。

代码整理：

- `数据二 = pd.DataFrame({`
- `'姓名': ['张三', '张三', '王五', '王五'],`
- `'班级': ['一班', '一班', '一班', '二班'],`
- `'分数': [40, 50, 60, 70]`
- `})`

### 5.3 多键内连接

代码：

- `数据三 = pd.merge(数据一, 数据二, on=['姓名', '班级'])`
- `print(数据三)`

执行逻辑：

- 用左表数据一的 `姓名` 和 `班级` 两个字段，去匹配右表数据二的 `姓名` 和 `班级`。
- 默认内连接，只保留两个表中都存在的组合。
- 数据一中的 `(张三, 一班)` 在数据二中有两个匹配行，因此结果中会产生两行。
- 数据一中的 `(王五, 一班)` 在数据二中有匹配行，因此被保留。
- 数据一中的 `(张三, 二班)` 在数据二中没有匹配，因此默认内连接中不出现。

结果列名：

- 两个表都有 `分数` 列，连接后 pandas 会自动加后缀区分。
- `分数_x` 表示左表数据一中的分数。
- `分数_y` 表示右表数据二中的分数。

讲师强调：`分数_x` 是数据一里的分数，`分数_y` 是数据二里的分数。

### 5.4 多键全外连接

在多键连接基础上增加 `how` 参数：

- `pd.merge(数据一, 数据二, on=['姓名', '班级'], how='outer')`

全外连接结果：

- 两个表中所有组合都保留。
- 没有匹配的地方显示为空值 `NaN`。
- 数据一中无匹配的 `(张三, 二班)` 会保留。
- 数据二中无匹配的 `(王五, 二班)` 等也会保留。
- 讲师说明：全外连接就是没有的地方显示为空。

多键连接也可以改成左连接或右连接：

- `how='left'`：左连接。
- `how='right'`：右连接。
- 只需修改 `how` 参数即可。

## 6. 基于索引的连接：left_on + right_index

### 6.1 使用场景

有时右表的连接键不是普通列，而是索引列。

- 可以把索引改回普通列再连接。
- 但如果数据量很大，修改索引不方便。
- 这种情况下可以直接基于索引做连接。
- `merge` 支持左表普通列与右表索引列连接。

### 6.2 索引连接示例数据

数据一示例：

- 姓名列：张三、李四、王五、张三、李四。
- 次数列使用 Python 的 `range(5)` 生成，即 0、1、2、3、4。
- 数据一默认索引为 0、1、2、3、4。

代码整理：

- `数据一 = pd.DataFrame({`
- `'姓名': ['张三', '李四', '王五', '张三', '李四'],`
- `'次数': range(5)`
- `})`

数据二示例：

- 数据值为 10 和 20。
- 使用 `张三`、`李四` 作为索引。

代码整理：

- `数据二 = pd.DataFrame({`
- `'数据': [10, 20]`
- `}, index=['张三', '李四'])`

打印后：

- 数据一有默认索引 `0~4`，姓名列包含张三、李四、王五、张三、李四。
- 数据二的索引为 `张三`、`李四`，对应数据值为 10、20。

### 6.3 用左表列连接右表索引

代码：

- `数据三 = pd.merge(数据一, 数据二, left_on='姓名', right_index=True)`
- `print(数据三)`

参数说明：

- `left_on='姓名'`：指定左表数据一中用于连接的列是 `姓名`。
- `right_index=True`：告诉 `merge` 使用右表数据二的索引作为连接键。
- `right_index` 默认是 `False`，这里必须显式改成 `True`。
- 含义是：用左表的 `姓名` 列去连接右表的索引列。
- 默认仍然是内连接，因此只保留姓名与右表索引匹配的行。
- 王五在右表索引中没有匹配，因此默认内连接中被丢弃。
- 张三、李四在右表索引中有匹配，因此带出右表的数据值。
- 左表中张三、李四出现多次，右表索引中各有一个匹配值，因此结果中会按左表匹配行重复带出右表值。

### 6.4 索引连接的其他连接方式

可以继续指定 `how`：

- `pd.merge(数据一, 数据二, left_on='姓名', right_index=True, how='outer')`

说明：

- 使用 `how='outer'` 后变为全外连接。
- 没有匹配的地方显示为空值 `NaN`。
- 同理可以改成 `how='left'` 或 `how='right'`。
- 讲师再次强调：默认是内连接，可以不写；其他连接方式一定要手工写上 `how`。

## 7. 关键结论与易错点汇总

- `pd.merge` 类似 SQL 的 `join`，用于两个 `DataFrame` 按共有列连接。
- `concat` 是合并，`merge` 是连接查询，两者概念不同。
- 内连接类似 Excel 的 `VLOOKUP`，但 `merge` 是按列匹配连接。
- `merge` 默认连接方式是内连接 `inner`。
- 默认内连接只保留两个表连接键相交的部分。
- 左连接以左表为基准，右表无匹配处为 `NaN`。
- 右连接以右表为基准，左表无匹配处为 `NaN`。
- 全外连接保留两个表的所有内容，无匹配处为 `NaN`。
- 单键连接使用 `on='字段名'`。
- 多键连接使用 `on=['字段1', '字段2']`，多个键要放在列表中。
- 使用 `how` 指定连接方式：`inner`、`left`、`right`、`outer`。
- 内连接且使用同名共有列时，`on` 和 `how='inner'` 可以省略。
- 其他连接方式必须显式写 `how`。
- 连接后同名列会自动加后缀，如 `分数_x`、`分数_y`；`_x` 通常对应左表，`_y` 对应右表。
- 左表列连接右表索引时使用 `left_on='列名', right_index=True`。
- `right_index` 默认是 `False`，必须手工改为 `True`。
- 如果右表索引是连接键，不必先把索引改回普通列；大数据量时直接连接更方便。
- 姓名等字段可以重复，连接会产生多对一、一对多或多对多匹配关系，结果行数可能扩展。
- `merge` 还有很多高级用法，本节暂不展开，后续用到时再介绍。
