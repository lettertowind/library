# 手机链接 → 网站更新

## 一句话

把 B站 分享链接发给我，剩下的全自动。

```
B站链接  →  笔记  →  概念卡片  →  网站  →  手机可看
```

线上地址：https://lettertowind.github.io/library/

---

## 它做了什么

1. **解析链接**：支持 `b23.tv` 短链、`m.bilibili.com` 手机版、带 `?share_source=` 等参数的分享文本，统一还原成 `https://www.bilibili.com/video/BVxxx`
2. **确保后端在跑**：BiliNote 后端没运行时自动拉起（源码方式，约 10 秒），不依赖桌面窗口
3. **生成笔记**：下载字幕或转写音频，交大模型整理成详细笔记
4. **抽取概念**：拆成概念卡片。已有同名概念只在末尾追加 `### 补充`，不会重复建卡
5. **重建站点**：首页、概念页、领域页、搜索索引全部重新生成
6. **推送 GitHub**：提交并推送，GitHub Pages 自动重新部署

**注意**：推送到线上生效有 1–2 分钟延迟，这是 GitHub Pages 的构建时间，不是脚本能控制的。

## 手动运行

```bash
cd D:\知识库\_馆务
python pipeline.py "https://b23.tv/xxxx"
```

参数：

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只解析链接、检查环境，不提交任务 |
| `--note-only` | 只生成笔记，停在 `_在编`，不抽概念不发布 |
| `--no-publish` | 抽概念、生成站点，但不推 GitHub |
| `--model xxx` | 指定模型，默认 `deepseek-flash` |

也可以直接双击 `_馆务\处理链接.bat`，把链接粘进窗口。

## 常见问题

**`ffmpeg missing`**
`.env` 里 `FFMPEG_BIN_PATH` 要填**目录**（不是 exe 路径）。缺它会报 `unable to obtain file audio codec with ffprobe`，下载阶段直接失败。

**`没有可用的供应商`**
`backend/bili_note.db` 的 `providers` 表里 deepseek 的 `api_key` 是空的。`base_url` 必须是 `https://api.deepseek.com/v1`，写成 `platform.deepseek.com` 会被 Cloudflare 拦。

**下载卡住或 API 报错**
本机有全局代理（`127.0.0.1:54730`），会干扰 B站 下载和大模型调用。脚本启动后端时已清空 `HTTP_PROXY` 等变量。

**桌面版和脚本会不会冲突**
不会。桌面版开着（占 8483）时脚本直接复用它；没开就自己拉起源码后端。两者不要同时启动后端即可。

**手机端看到旧内容**
等 1–2 分钟，或去仓库 Actions 页看部署是否完成。

## 相关文件

| 文件 | 作用 |
|---|---|
| `_馆务/pipeline.py` | 本条链路的全部逻辑 |
| `_馆务/curator.py` | 从笔记抽概念、写卡片 |
