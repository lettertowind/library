# 手机链接 → 网站更新

## 一句话

把 B站 分享链接发给我，剩下的全自动。

```
B站链接  →  笔记  →  概念卡片  →  网站  →  手机可看
```

线上地址：https://lettertowind.github.io/library/

---

## 它做了什么

1. **解析链接**：支持 `b23.tv` 短链、`m.bilibili.com` 手机版、带 `?share_source=` 等参数的分享文本，统一还原成 `https://www.bilibili.com/video/BVxxx`
2. **确保后端在跑**：BiliNote 后端没运行时自动拉起（源码方式，约 10 秒），不依赖桌面窗口
3. **生成笔记**：下载字幕或转写音频，交大模型整理成详细笔记
4. **抽取概念**：拆成概念卡片。已有同名概念只在末尾追加 `### 补充`，不会重复建卡
5. **重建站点**：首页、概念页、领域页、搜索索引全部重新生成
6. **推送 GitHub**：提交并推送，GitHub Pages 自动重新部署

**更新速度**：实测从推送完成到线上生效约 **30 秒**（推送 10 秒 + 部署 23 秒）。服务端 CDN 没有额外延迟。

手机上如果看到旧内容，是浏览器的缓存（GitHub Pages 对 HTML 设了 `max-age=600`）。**下拉刷新**即可，页脚有精确到分钟的更新时间可以核对。

## 手动运行

```bash
cd D:\知识库\_馆务
python pipeline.py "https://b23.tv/xxxx"
```

参数：

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只解析链接、检查环境，不提交任务 |
| `--note-only` | 只生成笔记，停在 `_在编`，不抽概念不发布 |
| `--no-publish` | 抽概念、生成站点，但不推 GitHub |
| `--model xxx` | 指定模型，默认 `deepseek-flash` |

也可以直接双击 `_馆务\处理链接.bat`，把链接粘进窗口。

## 合集逐集深挖

单个链接只处理一集。要把整季（如 Numpy 13 集、Pandas 32 集）都做成笔记，用批量脚本：

```bash
cd C:\Users\Sean\WorkBuddy\spaces\2026_11_16_19-04-52
python batch_numpy_pandas.py
```

它会按 `?p=N` 逐集提交、只生成笔记不停在抽概念，进度记在 `batch_ledger.json`，中断后重跑会自动跳过已完成的集。跑完再统一执行一次：

```bash
cd D:\知识库\_馆务
python curator.py     # 45 篇笔记一次性抽概念
python site.py        # 重建站点
python sync.py "提交说明"
```

实测（45 集 / 13.3 小时）：逐集笔记约 45 分钟，抽概念约 5 分钟。比一集一跑 `pipeline.py` 省事，也不会反复重建索引。

## 常见问题

**`ffmpeg missing`**
`.env` 里 `FFMPEG_BIN_PATH` 要填**目录**（不是 exe 路径）。缺它会报 `unable to obtain file audio codec with ffprobe`，下载阶段直接失败。

**`没有可用的供应商`**
`backend/bili_note.db` 的 `providers` 表里 deepseek 的 `api_key` 是空的。`base_url` 必须是 `https://api.deepseek.com/v1`，写成 `platform.deepseek.com` 会被 Cloudflare 拦。

**`ModuleNotFoundError: No module named 'openai'`**

`curator.py` 用 openai SDK 调模型，这包装在跑 `pipeline.py` 的那个解释器里，不是 BiliNote 后端的虚拟环境。报错就执行 `python -m pip install openai`，装完 `curator.py` 即可正常抽概念（笔记阶段不受影响，只有第 5 步会失败）。

**下载卡住或 API 报错**
本机有全局代理（`127.0.0.1:54730`），会干扰 B站 下载和大模型调用。脚本启动后端时已清空 `HTTP_PROXY` 等变量。

**跑一半没动静了（尤其过夜）**

两个已知死法，都在 2026-11 修补过：

- **BiliNote 后端卡在「下载中」**：音频文件已经下完但状态不再推进，任务永远停在那一步。表现为批量脚本十几分钟没有任何新输出。处理办法是杀掉后端进程（`Stop-Process -Name python`，注意别杀错成本机的其他 python）、删掉 `_在编` 里该任务的残留状态文件，然后重跑批量脚本——它会从断点继续。
- **抽概念时挂在一次请求上**：机器休眠会断掉连接，`curator.py` 已给请求加 180 秒超时与重试，不会再永久挂起。若在旧版本上遇到整夜无输出、进程 CPU 几乎不涨，就是这个问题，杀掉重跑即可（已抽的卡会走「补充」流程，不会重复建卡）。

**批量整理后卡片碎片化**

一次跑几十集，模型会倾向给单个参数单独建卡（`sep 参数`、`ignore_index 参数`、`np.exp`、`dtypes 属性`）。`SYSTEM_PROMPT` 里已加禁止条款，但「已有概念」列表本身会被模型模仿——如果库里已经堆了一批参数卡，清理干净后模型才会收敛。建议每季深挖后花十分钟扫一遍 `概念/`，把纯参数卡删掉或并进所属函数卡。

**桌面版和脚本会不会冲突**
不会。桌面版开着（占 8483）时脚本直接复用它；没开就自己拉起源码后端。两者不要同时启动后端即可。

**手机端看到旧内容**
刷新的问题，不是发布失败。GitHub Pages 给 HTML 设了 10 分钟缓存，**下拉刷新**一下即可。页脚的更新时间精确到分钟，可以对照。CSS/JS 已加内容版本号，样式改动不需要手动清缓存。

**链接是个几十集的合集**

B站 合集的所有分P共用一个 BV 号，`b23.tv` 短链经常落在 p1——而不少 UP 主的 p1 是开场曲或预告。脚本会老老实实把它转写完，产出一篇和标题毫无关系的废话笔记（实测：孙兴华那套三部曲的 p1 就是 3 分钟开场曲，转写全是歌词）。跑之前先看 `pages` 长度：

```bash
curl -s "https://api.bilibili.com/x/web-interface/view?bvid=BVxxxx" | python -c "import json,sys;d=json.load(sys.stdin)['data'];print(d['videos'],'P / 共',d['duration']//60,'分钟');[print(p['page'],p['duration'],p['part']) for p in d['pages'][:15]]"
```

集数多就先做课程地图（分P目录整理成一篇 `分析/` 笔记 + 一张 `概念/` 总览卡），别逐集转录；要深挖哪集再单独跑。
