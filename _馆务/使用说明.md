# 使用说明

## 这是什么

一座用概念卡片搭起来的知识库。不是按视频存档，而是把一个名词拆成一张卡：**定义 → 解释 → 用处 → 要点 → 关联 → 自测**。卡片之间用双链连成网，靠双链和 MOC 组织，不靠文件夹层级。

一条视频进来，会被拆成 3-8 张卡片；同一个概念再次出现时，是往旧卡上补，不是新建一张。

## 卡片长什么样

以「提示工程」为例：

```markdown
---
term: 提示工程
aliases: [Prompt Engineering]
kind: method
domain: AI/大模型
tags: [概念/method, 领域/AI]
created: 2026-11-16
updated: 2026-11-16
---

# 提示工程

> 别名：Prompt Engineering

**通过结构化输入约束大模型输出空间的方法。**

## 解释
...

## 有什么用
- ...

## 关键要点
- ...

## 边界与易混淆
...

## 关联
- [[大语言模型]] — 上位概念
- [[少样本学习]] — 组合使用

## 自测
提示工程解决的核心问题是什么::让输出可控、可复现

## 出处
- [视频标题](url) · 2026-11-16
```

## 一篇视频进来之后

```
_在编/某视频笔记.md
      ↓  整理概念
概念/提示工程.md、概念/上下文窗口.md、概念/少样本学习.md ……
      ↓  自动刷新
概念索引.md · MOC/计算机.md · 首页.md
      ↓  原件归档
_典藏/2026-11/
```

同一概念第二次出现时，会在卡片末尾追加 `### 补充 · 日期` 一节，写新观点、新来源，原有定义不动。

## 三个查阅入口

| 入口 | 用途 |
|---|---|
| `首页.md` | 概览、领域分布、待补全词条 |
| `概念索引.md` | 全部概念，按领域分组 |
| `MOC/` | 各领域地图，一个领域一页 |

另外 Obsidian 自带的双链面板、图谱视图、标签面板都能直接用。点开任一卡片，右侧「反向链接」会显示哪些概念引用了它。

## 复习

已装 **Spaced Repetition** 插件。卡片里 `## 自测` 下的 `问题::答案` 会被识别成单行卡。

- 左侧边栏点卡片图标，或命令面板搜 `Review flashcards`
- 按遗忘曲线排期，右下角评「记得/模糊/忘了」会影响下次间隔
- 想临时看一眼：命令面板搜 `Open random note` 随机抽卡

第一次用建议在插件设置里把「New cards per day」设成 10-20，别一次压太多。

## 日常操作

**手动整理**：双击 `_馆务/整理概念.bat`

**先看再落盘**：`整理概念.bat --dry-run`，只打印会建/会补哪些概念

**自动整理**：双击 `_馆务/后台整理.bat` 常驻，新素材静止 25 秒后自动处理

**在 Obsidian 里触发**：设置 → Shell commands → 新建命令：

```
cmd /c "D:\知识库\_馆务\整理概念.bat"
```

## 维护规则

**同名即合并**：卡片文件名就是概念名，再出现时按文件名、term、别名比对，命中就补充。所以别名很重要，`Prompt Engineering` 和 `提示工程` 会走到同一张卡。

**双链可以指向不存在的卡**：`[[注意力机制]]` 就算还没有这张卡也能写，Obsidian 显示成灰色待建链接。首页会汇总这些「待补全词条」，按被引用次数排序，提示你哪些概念最值得补。

**领域是层级标签**：`domain` 写成 `AI/大模型`，同时生成标签 `#领域/AI`。MOC 按第一段分文件，索引按完整路径分组。

**卡片可以手改**：编目员只在末尾追加「补充」，不会覆盖你写的解释和要点。手改后 frontmatter 别删 `term`，否则下次比对不到。

## 边界

- 只抽「值得单独查阅的概念」，观点和论述会落到概念的要点里，不单独成卡
- 不自动删除卡片，概念过时了自己删
- 不做跨卡片的知识重构（比如自动重写某领域体系），只做增量
- 抽得太细（把一句话拆成三个概念）比抽得太粗更容易出错，发现后调 `_馆务/curator.py` 里的 SYSTEM_PROMPT

## 维护：让 AI 对已有概念自我调节

双击 `_馆务/知识库.bat` 打开中文菜单，六个入口：

| 序号 | 功能 | 说明 |
|---|---|---|
| 1 | 整理新素材 | 从 `_在编` 抽概念，同名补充 |
| 2 | 体检 | 查重复、矛盾、失效、错位、孤岛、缺链 |
| 3 | 合并概念 | 重复的并成一张，旧卡进 `_废弃`，全库双链自动改指主卡 |
| 4 | 下架概念 | 移到 `_废弃`，不真删，随时可捞回 |
| 5 | 问知识库 | 检索相关卡片后作答，答案存进 `问答记录.md` |
| 6 | 重建索引 | 概念索引 / MOC / 首页 重新生成 |
| 7 | 写知识综述 | 基于现有概念生成一份体系综述，指出结构与空白 |

### 体检会查什么

- **重复**：同义词、中英文、缩写全称、近义表述，给出「保留谁、并入谁」
- **矛盾**：两张卡说法打架，或某条已被新结论推翻
- **失效**：版本已淘汰、事实已变、一次性信息
- **错位**：领域归属不对，或同一概念散在多个领域
- **孤岛**：没有任何关联的边缘卡片
- **缺链**：明显相关却没建立关联的概念对

体检**只出报告不动文件**，报告写到 `_馆务/报告/体检-日期.md`。看完报告再决定执行哪些合并和下架。

### 合并的处理方式

不是机械拼接。AI 会保留主卡框架，把被并入卡里**独有的信息**提取进来，重复内容丢掉。执行后：

1. 被并入的卡移到 `_废弃/年月/`
2. 全库扫一遍，`[[被并入的卡]]` 自动改成 `[[主卡]]`
3. aliases 里补上被合并的词条名，以后这些名字也会命中主卡

### 命令行等价写法

```bat
知识库.bat                 中文菜单
维护.bat audit             体检
维护.bat merge 保留 并入1 并入2
维护.bat prune 词条
维护.bat ask "问题"
维护.bat rebuild
```

## 交给任意 AI 接管

库根目录有 `AGENTS.md`，写的是这个库的完整操作规则：目录约定、卡片格式、四个标准操作、硬性规则、禁止事项。

任何 AI Agent 打开 `D:\知识库` 作为工作目录，会先读它，然后就能按规则摄入素材、体检、问答、合并下架——不需要你在对话里重新解释一遍规则。

改规则只改 `AGENTS.md` 一处。脚本里的 prompt 是同一套思路的实现，改完可以顺手同步。

## 分析目录

`分析/` 存两类东西：

| 类型 | 来源 | 说明 |
|---|---|---|
| 问答沉淀 | 问知识库时自动生成 | 一个有价值的问题 + 结论 + 依据（带双链） |
| 体系综述 | 菜单 7 生成 | 当前知识全貌、领域结构、明显空白 |

问答沉淀的意义：你问出来的东西本身就是知识，不沉淀下次还得再问一遍。综述的意义：卡片是点，综述是面，能看出哪里空、哪里重复。

## 定期体检

`后台整理.bat` 常驻时，每 7 天会自动生成一次体检报告（只出报告，不动卡片）。条件是有 5 张以上卡片。

报告堆在 `_馆务/报告/`，有空翻一下就行，不用每天看。
