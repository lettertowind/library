# 连接键

> 别名：on、join key、on 参数、连接字段

**两张表拼接时用于判断「哪一行对哪一行」的那一列（或多列）。**

## 解释

merge 的本质是按某个共同字段把两张表的行对齐，这个字段就是连接键；在 pd.merge 中用 on 参数指定，如 on='学号'。没有连接键，merge 只能做无意义的笛卡尔积。连接键不要求列名完全相同，不同名时用 left_on / right_on 分别指定。

## 有什么用

- 把两张表的同一实体的不同属性拼到一起（如花名册 + 成绩单）
- 替代 Excel 的 VLOOKUP 查找列

## 关键要点

- on='学号' 表示左右表都用「学号」这一列对齐
- 连接键应尽量唯一，否则会产生一对多膨胀行数
- 左右列名不同时改用 left_on 与 right_on
- 右表只需保留连接键 + 目标列，其余列先筛选掉再做 merge

## 边界与易混淆

on 只适用于左右表列名一致的情况；列名不一致而误用 on 会直接报 KeyError。

## 自测

两张表列名不同（左表叫 uid、右表叫 user_id），用 on 能连吗？该用什么？::不能，on 要求同名；应改用 left_on='uid', right_on='user_id'。
为什么做 VLOOKUP 式匹配时要先裁掉右表的无关列？::merge 会把右表所有列带进结果，列太多会污染结果表；只留连接键和目标列最干净。


### 补充 · 2026-11-17

连接键决定「什么样的两行算同一行」。实际业务里一般是 id、索引、序号；同名共有列可交给 merge 自动识别，不同名或要连索引时才需要额外参数。

- 两表存在同名共有列时，on 可以省略，merge 自动用它作键
- 多个键写进列表：on=['姓名', '班级']，要求同时相等
- 键不同名时用 left_on/right_on 分别指定
两表都有「姓名」列，但业务上应该按 id 匹配，直接 pd.merge(a, b) 会怎样？::merge 会用同名「姓名」列做内连接，可能错配同名不同人；必须显式写 on='id' 指定真正的连接键。
