# Series 索引取值

> 别名：数据["键"]、多键查询、Series 取值

**用中括号传入索引标签，从 Series 中取出对应值；取多个标签需先包成列表。**

## 用法
**语法**：`Series[key]` / `Series[[key1, key2, ...]]`
**参数**：
- `key`：单个索引标签，返回该标签对应的标量值。
- `[key1, key2, ...]`：标签列表，返回子 Series；多键必须包成一个列表对象。
- 切片：语义随索引类型变化，严格按标签取值建议改用 `s.loc[...]`。
**示例**：
```python
import pandas as pd

s = pd.Series([90, 85, 88], index=["孙悟空", "猪八戒", "沙和尚"])
print(s["孙悟空"])                 # 90
print(s[["孙悟空", "沙和尚"]])     # 孙悟空    90
                                  # 沙和尚    88
                                  # dtype: int64
print(type(s[["孙悟空", "沙和尚"]]))  # <class 'pandas.core.series.Series'>
```

## 解释

Series 的中括号只接受一个对象参数。传单个键返回该位置的值本身；要一次取多个键，必须把键组成列表再传进去。理解这一点能避免「多键并列写」这种最常见的报错。

## 有什么用

- 按业务标签（姓名、性别、年龄）取出某个字段值
- 一次取出多个字段做对比或再计算

## 关键要点

- 单键写法：数据["姓名"]，返回的是单个值
- 多键写法：数据[["姓名", "性别"]]，标签必须包在列表里
- 写成 数据["姓名", "性别"] 会报错，中括号不接收两个并列参数
- 多键查询的结果仍然是 Series，而非普通值
- 是否为标签或位置取决于索引类型，语义严格时改用 loc

## 边界与易混淆

与 loc 的区别：中括号取值在位置切片和标签取值间语义含糊，明确按标签取时用 loc 更安全。

## 自测

为什么 数据["姓名", "性别"] 会报错，而 数据[["姓名", "性别"]] 可以？::中括号只接收一个对象；前一种传了两个并列参数，后一种把两个键组成一个列表作为一个对象传入。
多键查询后得到的是单值还是 Series？::仍然是一个 Series（一维数据结构）。
