# 浅拷贝与深拷贝

> 别名：copy、视图、view vs copy、独立副本

**直接赋值和切片共享底层数据（浅拷贝），copy() 才创建独立副本。**

## 解释

在 NumPy 中 a = b 或 a = b[:] 往往让两者共享同一份数据，改一个另一个也变。用 b.copy() 得到深拷贝，两者互不影响。这是极易出错的地方。

## 有什么用

- 需要独立修改数组而不影响原数组时
- 避免切片视图带来的意外联动

## 关键要点

- a = b 是同一份数据的两个名字
- 切片通常返回视图，仍共享数据
- b.copy() 创建独立副本
- 赋值前先判断是否需要 copy

## 边界与易混淆

视图省内存但易引发联动 bug；深拷贝安全但占内存。

## 自测

a = b[:] 之后修改 b，a 会变吗？::会，切片是视图，共享底层数据。
怎样让两个数组完全独立？::用 b.copy() 创建深拷贝。


### 补充 · 2026-11-17

NumPy 中 a = b 只是给同一块内存起了第二个名字，a = b[:] 得到的是视图，数据仍由 b 保管；只有 b.copy() 会真正复制数据。不区分这两者，会出现「改了 b，a 也变了」的隐蔽 bug。

- a = b 是别名，两者指向同一份数据，互相影响
- 切片 a = b[:] 是视图，改任意一方另一方都变
- b.copy() 得到独立副本，双向修改互不影响
a = b 之后修改 b 的元素，a 会跟着变吗？为什么？::会变，因为 a 和 b 指向同一块内存，只是两个名字。
切片得到的数组和 copy() 得到的数组，本质区别是什么？::切片是视图，与原数组共享底层数据；copy() 会复制一份独立数据。
