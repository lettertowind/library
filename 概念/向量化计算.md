# 向量化计算

> 别名：vectorization、向量化运算

**对整个数组直接做整体运算，替代显式循环逐元素处理。**

## 解释

向量化让 a + b 直接完成逐元素相加，无需 for 循环和下标追加。底层由编译好的 C 代码执行，代码更短、速度更快。

## 有什么用

- 数组逐元素运算
- 替代 Python for 循环提升性能

## 关键要点

- 写法上省去 for 循环和 append
- 数据量越大，相对普通循环的优势越明显
- 是 NumPy 高效的核心原因之一
- 可与通用函数、广播机制组合使用

## 边界与易混淆

小数据量时性能差距不明显，不必为微小数据强行改写。

## 自测

为什么 NumPy 的 a + b 比 Python 的 for 循环逐项相加快？::因为它在底层用编译代码对整个数组整体运算，避免了 Python 层的循环开销。
数据量很小时，向量化的优势是否明显？::不明显，数据量增大后优势才突出。


### 补充 · 2026-11-17

向量化把循环下沉到编译好的底层代码中执行，既让代码更短，也大幅提升速度。通用函数正是向量化的具体实现：写的是函数调用，跑的是整数组并行式运算。

- 以数组为单位书写，代码中不再出现显式循环
- 底层由编译代码执行，速度远快于 Python 循环
- 通用函数是向量化最直接的表现形式
用 np.sqrt(a) 和用 for 循环逐元素开方，结果一样，为什么还推荐前者？::前者把循环放到编译层执行，代码更短且在大数据量下明显更快，也更容易与广播等机制组合。

NumPy 把循环下沉到 C 层执行，并对连续内存做批量处理，所以写起来更短、跑起来更快。它解决的是 Python 原生 for 循环做数值计算又慢又啰嗦的问题。数据量越大，与纯 Python 写法的差距越明显。

- 代码层面看不到 for，循环由底层 C 完成
- 相比列表 + for + append，省去建函数、建空列表、逐项追加
- 数据量越大优势越明显，可能快几倍到十几倍
向量化为什么比 Python for 循环快？::因为循环在 C 层对连续内存批量执行，避免了逐元素的 Python 解释器开销。
什么情况下向量化不一定更快？::数据结构不规则、类型混杂或无法用连续数组表示时，向量化优势会消失。
