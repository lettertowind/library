# 布尔索引筛选

> 别名：布尔索引、条件筛选、数据['部门']==i

**用布尔条件序列筛选 DataFrame 中符合条件的行。**


## 用法
**语法**：`df[df['列'] == 值]`、`df[(条件1) & (条件2)]`、`df.loc[条件]`、`df[~条件]`
**参数**：布尔索引不是函数，没有形参；下面是要放进方括号里的「条件」要素。
- `条件`：与原 `df` 行数一致、dtype 为 `bool` 的 Series 或数组，长度对不上会报错
- `==` `!=` `>` `<` `>=` `<=`：比较运算符，判等必须用 `==`（`=` 是赋值）
- `&` `|` `~`：与 / 或 / 非，组合多个条件时每个条件都要用括号包住
- `isin([...])`：多值匹配，比一串 `|` 更清晰
- `isna()` / `notna()`：条件列含缺失值时该行默认不被选中，需要时显式判断
- `df.loc[条件, 列]`：筛行同时只取部分列；`df.loc[条件, '列'] = 值` 可原地改写子集
**示例**：
```python
import pandas as pd

df = pd.DataFrame({'部门': ['A', 'B', 'A', 'B'], '销量': [10, 20, 30, 40]})

print(df[df['部门'] == 'A']['销量'].tolist())                        # [10, 30]
print(df[(df['部门'] == 'A') & (df['销量'] > 15)]['销量'].tolist())   # [30]
print(df.loc[df['销量'].isin([10, 40]), '销量'].sum())               # 50
print(df[df['销量'].isna()].shape[0])                               # 0
```

## 解释

把条件表达式（如 数据['部门']==i）作为索引传给 DataFrame，返回条件为真的行。它是拆分任务中“取出某一组数据”的标准写法，比较必须用 ==。

## 有什么用

- 按部门取出子表
- 按条件过滤数据行
- 拆分前筛选目标分组

## 关键要点

- 写法：数据[数据['部门'] == i]
- 比较相等用 ==，= 是赋值会报错或出错
- 多个条件用 & 连接并加括号
- 返回的是原数据的子集副本

## 边界与易混淆

条件列含缺失值时该行不会被选中；字符串比较对空格和大小写敏感。

### 补充 · 2026-11-17

布尔索引先用条件表达式生成与原数组形状相同的布尔数组，再用它作为下标。True 位置被保留或赋值，False 位置被过滤或跳过。它是 Numpy 中按条件批量定位元素的核心手段。

- 本质：条件表达式生成布尔数组，再作为下标使用
- 一维筛选写法：arr[arr > 5]
- 条件赋值写法：arr[arr > 5] = 1、arr[arr > 5] += 520
arr2d[arr2d > 10] 返回的形状是什么？为什么？::返回一维数组，因为布尔筛选会把所有满足条件的元素提取出来并压平，不保留原二维形状。
要把二维数组第三列中大于 5 的元素改为 520，直接写 arr2d[arr2d > 5] = 520 有什么问题？::会把整个数组中所有大于 5 的元素都改成 520，而不只是第三列，作用范围错误。

把布尔 Series 直接放进方括号 tt[条件]，Pandas 会按位置对齐取出为 True 的行。它本身不产生判断，需要 duplicated、比较运算等先给出布尔结果。做「提取重复行」时建议先把布尔结果存成变量再切，避免重复计算和可读性问题。

- 写法 tt[dup]，dup 为长度相同的布尔 Series
- 先用 dup = tt.duplicated(subset='姓名') 存变量再切片更清晰
- 布尔结果与行按索引对齐，长度不一致会报错
dup = tt.duplicated('姓名') 之后 tt[dup] 得到什么？::得到所有被判定为重复的行，即除首次出现外的重复记录明细
为什么建议先把布尔结果保存成变量再切片？::涉及切片时表达式嵌套易出错、可读性差，先存变量还能复用结果

把比较表达式（如 数据['语文'] >= 60）得到的一列 True/False 放进中括号，Pandas 就只返回对应为 True 的行。多个条件用 & 组合并各自加括号，就构成了复合筛选。loc 中的条件查询本质上也是布尔索引。

- 形如 df[df['列'] > 阈值]，掩码与原表行对齐
- 多条件用 & 连接，每个条件加小括号
- 写成 loc[条件, :] 语义更明确，等价于直接中括号
df[df['语文'] >= 60][['姓名','数学']] 与 df.loc[df['语文'] >= 60, ['姓名','数学']] 有什么区别？::结果相同，后者用一次 loc 同时指定行条件和列选择，写法更直接，也不易在链式索引上产生歧义。

布尔索引先用比较或逻辑运算得到一个与原数组形状相同的布尔数组，再把它放进方括号里作为下标。下标中为 True 的位置被保留，为 False 的位置被丢弃，因此它是「按条件取数」而不是「按位置取数」。它既能出现在读取语句里筛选数据，也能出现在赋值语句左侧做条件修改。

- 两步走：先用条件生成布尔数组，再把它当数组下标
- arr[arr > 5] 与 mask = arr > 5; arr[mask] 完全等价
- 布尔索引可放在赋值号左侧，只改 True 对应位置的元素
arr2 是二维数组，执行 arr2[arr2 > 10] 后结果是什么形状？为什么？::一维数组。布尔索引对每个元素单独判断，把所有 True 位置的值抽出来拼成一维，不保留原二维形状。
要把二维数组第三列中大于 5 的值改成 520，为什么 arr2[arr2[:, 2] > 5] = 520 是错的？::arr2[:, 2] > 5 得到的是行条件，arr2[行条件] 选中的是整行，赋值会改掉整行所有列；正确写法是 arr2[:, 2][arr2[:, 2] > 5] = 520。
