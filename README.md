# 个人知识库工作流

> 把刷到的 B站 视频，自动变成**手机上可查、可复习、会自己生长**的概念知识库。

一句话说完它做什么：

```
手机发一条 B站 链接  →  AI 拆成概念卡片  →  生成网站  →  手机随时查阅和复习
```

线上演示：[lettertowind.github.io/library](https://lettertowind.github.io/library/)

---

## 它解决什么问题

大多数人收藏知识的过程是这样的：刷到好视频 → 点收藏 → 再也不看。收藏夹里躺着几百条链接，等于没有。

这套系统针对的是三个具体痛点：

| 痛点 | 它的做法 |
|---|---|
| 收藏了就等于掌握了？ | 一条视频不是存成一篇文章，而是拆解成 3–12 张**概念卡片**，每张有定义、用处、要点、边界、关联、自测题 |
| 笔记越攒越乱，找不到？ | 卡片之间用双链连成网；按领域自动生成 MOC 地图；搜索本地即时响应 |
| 知识只进不出，不会用？ | 关联网谱看关系、自测题按遗忘曲线复习、问答结果回沉为新知识、AI 定期体检合并 |

核心判断：**知识的价值在调用，不在存储。** 所以整套设计都围绕「怎么让一条知识以后还能被精准找到并串起来」。

---

## 一次摄入会发生什么

你在手机上把 B站 分享链接发给 Agent（或双击一个 bat 粘进去），之后全自动：

```
① 解析链接        b23.tv 短链、手机版链接、带参数的分享文本 → 统一成标准 BV 地址
② 拿到内容        优先抓官方字幕；拿不到就下载音频本地转写
③ 大模型整理      生成结构化详细笔记（定义/要点/逻辑）
④ 抽取概念        拆成一批概念卡片；同名概念自动「补充」而非重复建卡
⑤ 建立关联        与已有卡片建立双链，标注上位/下位/前置/对比/组合关系
⑥ 重建站点        首页、领域地图、概念页、搜索索引全部刷新
⑦ 推送上线        git push → GitHub Pages 自动部署，约 30 秒后可访问
```

全程无需手动整理。你唯一要做的就是发链接。

## 一张卡片长什么样

以「第二大脑」为例（实际产出的卡片）：

```markdown
---
term: 第二大脑
aliases: [Second Brain, PKM 系统]
kind: concept
domain: 知识管理/个人知识库
tags: [概念/concept, 领域/知识管理]
created: 2026-11-16
updated: 2026-11-16
---

# 第二大脑

**把外部信息持续摄入、组织、关联并可随时调用的个人知识系统。**

## 解释
第二大脑不是简单的笔记堆，而是一个能长期积累、被检索和复用的外部认知系统……

## 有什么用
- 长期积累行业知识
- 辅助写作与分析
- 把收藏内容转化为可复用知识

## 关键要点
- 核心价值在调用，不在存储
- 知识要拆成知识点而非整篇文章
- 知识点之间要建立关联形成网络

## 边界与易混淆
不等于网盘或收藏夹；没有摄入、拆分和关联的收藏不构成第二大脑。

## 关联
- [[Obsidian]] — 组合使用
- [[知识图谱]] — 下位概念
- [[AGENTS.md]] — 组合使用

## 自测
为什么说第二大脑的关键是调用而不是存储？::因为存储的文章再多，若不能精准定位和关联……

## 出处
- [视频标题](url) · 2026-11-16
```

`## 自测` 里的 `问题::答案` 会被 Obsidian 的间隔重复插件识别成闪卡；在网站上则渲染成折叠块——先自己想，再点开看答案。

## 系统构成

| 层 | 技术 | 作用 |
|---|---|---|
| 内容获取 | [BiliNote](https://github.com/JefferyHcool/BiliNote)（FastAPI + React，另有 Tauri 桌面版） | 取字幕/转写，调大模型生成笔记 |
| 知识存储 | [Obsidian](https://obsidian.md/) vault，纯本地 Markdown 文件 | 卡片、双链、图谱、复习插件 |
| 自动化 | `_馆务/` 下 6 个 Python 脚本 | 抽取、维护、建站、同步、监听、串联链路 |
| 规则中枢 | 库根 `AGENTS.md` | 任何 Agent 打开这个库，读它就知道怎么操作 |
| 发布 | GitHub Pages + `docs/` 静态站 | 手机浏览器访问，无需服务器 |
| 模型 | DeepSeek（可换任意 OpenAI 兼容供应商） | 笔记整理与概念抽取 |

关键设计：**知识库就是一堆普通 Markdown 文件，不锁在任何一个软件里。** Obsidian 能看，任何 Agent 能读写，GitHub 能版本管理，网站生成器能直接消费。

## 已有的能力

**摄入**
- 支持 b23.tv 短链、手机版链接、带分享参数的文本
- 同名概念自动合并：只追加 `### 补充 · 日期`，不重复建卡
- 别名识别：`Prompt Engineering` 和 `提示工程` 归到同一张卡

**维护**（Agent 读 AGENTS.md 后可执行）
- 体检：查重复、矛盾、失效、错位、孤岛、缺链六类问题，**只出报告不改库**
- 合并：保留主卡框架，提取被并卡的独有信息，全库改写 `[[旧名]]` → `[[主名]]`
- 下架：移到 `_废弃/`，不物理删除，随时可恢复
- 问答：只基于已有卡片作答，答案自动回沉为新知识
- 综述：定期生成知识体系全貌，指出结构空白

**查阅与复习**
- Obsidian 双链、反向链接、关系图谱
- 领域 MOC 地图、概念索引、自动生成的首页
- 间隔重复闪卡（手机、电脑共用进度）
- 网站端本地搜索、暗色模式、移动端适配

## 实际效果

截至当前，这个库已经积累 **290+ 张概念卡片**，覆盖知识管理、计算机等领域，全部由上述链路自动摄入、抽取和关联。

网站每次更新从推送到上线约 **30 秒**。GitHub Pages 对 HTML 有 10 分钟缓存，看到旧内容时下拉刷新即可，页脚有精确到分钟的更新时间可核对。

## 快速开始

完整的安装说明已经打包成一份提示词：**[`_馆务/安装提示词.md`](./_馆务/安装提示词.md)**。

日常只有三种操作：

| 我想做什么 | 怎么做 |
|---|---|
| 加一条新知识 | 发 B站 链接给 Agent，或双击 `_馆务/处理链接.bat` 粘贴链接 |

| 只更新网站 | 双击 `_馆务/发布.bat` |

## 几个设计取舍

**概念卡片，而非书籍或文章摘要。** 一条知识越小、越独立，越容易被复用和重新组合。以「一张卡 = 一个名词」为粒度，双链才有意义。

**维护动作必须审计与执行分离。** 体检只出报告，合并/下架要打印方案并等你确认。完全交给 AI 自动改库，出错时无法回滚。

**站点生成器用纯标准库。** 不引第三方 markdown 库，因为依赖越少越不容易坏。卡片语法高度规范，手写渲染器反而更可控。

**卡片平铺，不按目录树分类。** 一个概念常跨多个领域，放进层级目录就得二选一。用双链、标签和 MOC 组织，比文件夹灵活。

**用 GitHub Pages 而不是自建服务器。** 静态站够用，零运维成本，顺带拿到完整版本历史。代价是仓库必须 Public，见下方限制。

## 已知限制

| 限制 | 说明 |
|---|---|
| 仓库是 Public | GitHub 免费账户的私有仓库不支持 Pages，所以**不要往库里放任何敏感内容**。API Key 已在 `.gitignore` 中排除 |
| 手机端只读 | 手机负责浏览和复习；AI 维护脚本需要 Python 环境，在电脑上运行 |
| 浏览器缓存 | GitHub Pages 强制给 HTML 设 10 分钟缓存，看到旧内容下拉刷新 |
| 检索是关键词级 | 不是语义检索。搜「提示工程」能命中，搜「怎么让模型听话」未必 |
| 字幕质量有依赖 | 不配 B站 Cookie 时会退化成本地 whisper tiny 转写，专业名词错字会变多 |
| 视频平台 | 目前链路针对 B站 设计，其他平台需扩展解析逻辑 |
