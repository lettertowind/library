缓存

Prompt Caching · 缓存命中 · Cache Hit

把对话中没变化的前缀存起来复用，下次不再重新计算。

目录
解释有什么用关键要点边界与易混淆关联自测出处

解释

服务商会把前面没有变化的部分（系统提示词、长文档、历史对话）缓存下来，下一次请求直接复用，不再重新计算。复用成功叫缓存命中，价格会便宜很多——DeepSeek Flash 模型命中缓存的输入价格只有未命中的五十分之一。

有什么用

  • 长对话、重复同一份背景资料时大幅降成本
  • 降低响应延迟
  • 指导你怎么组织提示词

关键要点

  • 缓存的是从开头算起的连续前缀，不是中间任意一段
  • 命中越多次，省得越多
  • 前置内容保持稳定才能持续命中
  • 修改系统提示词或前面的历史会让后续缓存失效

边界与易混淆

缓存不是记忆：缓存只省计算、不改回答内容，也不帮模型「记住」什么。它和 上下文窗口 是两件事——窗口决定能放多少，缓存决定重复内容的计算成本。

关联

  • 上下文窗口相关概念
  • 系统提示词放进前缀保持稳定
  • Token按 Token 计费

自测

点开看答案，先自己想一想

为什么长聊时中途改系统提示词会让开销变大？
系统提示词在缓存前缀里，一改后面的缓存全部失效，下次要重新计算整段输入。
缓存能让模型记住之前聊的内容吗？
不能，缓存只复用计算、降低价格，不改变模型能看到的内容。
