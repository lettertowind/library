index_col 参数

index_col · 指定索引列

读取时指定某列作为行索引的参数，可传单列名或列表。

目录
解释有什么用关键要点边界与易混淆关联自测出处

解释

index_col 把文件中的某列设为 DataFrame 行索引，传列表则形成多级索引。索引是行标签，不是排序结果，两者不要混淆。

有什么用

  • 用业务字段作行标签
  • 构建多级索引便于分组查询

关键要点

  • 可传单列名或列名列表
  • 列表形式生成多级索引
  • 索引不是排序

边界与易混淆

索引与排序是不同概念；索引列默认不再作为普通数据列出现。

index_col=['姓名','入职日期'] 会产生什么结构？
以姓名和入职日期为层级的多级索引。

### 补充 · 2026-11-17

index_col='序号' 让该列在读取阶段就成为索引，不再作为普通数据列出现，等价于读入后再 set_index，但少一步且不产生多余列。

- 可传列名或列位置序号

- 设置后该列从数据列中消失，成为行索引

- 与 header=None + names 组合可一次读成目标结构

index_col 和读入后 set_index 有什么实质差别？
结果基本一致，index_col 在读取阶段完成，少一次操作且不会先产生一列冗余数据。

原表本身带「序号」这类主键列时，如果不设 index_col，pandas 会另造一个 0,1,2 的自动索引，结果多出一列冗余数据。指定后序号列升格为行索引，表格结构与原表一致。

- index_col='序号' 按列名指定，也可传列序号 0

- 不设时 pandas 自动生成 0 起的整数索引，易多出一列

- 写回 Excel 时索引也会被写入，位置在首列

原表首列已经是序号，读取时不设 index_col 会有什么后果？
pandas 会额外生成一列自动索引，序号列仍是普通列，写回后表格比原来多一列。

- 出处：孙兴华中文讲Python数据分析三部曲入门篇 Numpy教程 Pandas教程 Matplotlib教程 p19 S02E04.读取与修改Excel文件 · 2026-11-17

把 index_col 写成 [0, 1] 这样的列表，读取阶段就直接得到两层行索引，省去后续 set_index 一步。它与「先读后 set_index」二选一，效果等价，讲师更偏好前者。

- 传单个列名/列号 → 单层索引；传列表 → 多层索引

- 与 set_index([...]) 效果等价，二选一

- 读取时设置少一步操作，无需额外转换

想让源文件前两列直接成为两层行索引，读取时怎么写？
pd.read_excel(..., index_col=[0, 1])。

- 出处：孙兴华中文讲Python数据分析三部曲入门篇 Numpy教程 Pandas教程 Matplotlib教程 p35 S02E20.多层索引与多层索引计算 · 2026-11-17

默认读取后行索引是 0、1、2… 连续编号，筛选子集时索引值会保留原位置，导致不同对象的第一项索引不同。设置 index_col 后索引变为业务字段，取值定位更稳定。

- 写法：pd.read_excel(..., index_col='姓名')

- 索引变为姓名后，该列不再作为普通数据列出现

- 雷达图场景中可保证每个对象都能用 [0] 取到本人第一项

不设 index_col 时，a02[0] 为什么可能取不到 a02 的第一个分数？
因为筛选结果保留原始行索引，a02 的首行索引可能是 5，[0] 指向的并不是它自己的第一项。
