遍历分组

for i · j in groupby · 分组迭代 · groupby 迭代

用 for 循环迭代 groupby 对象，每次得到分组键和对应子 DataFrame。

目录
用法解释有什么用关键要点边界与易混淆关联自测出处

用法

语法：for key, group in df.groupby(by) 参数：

  • by：分组依据，可以是列名、列名列表或 Series；传入多个列名时，key 是元组
  • key：每次迭代得到的第一个值，即分组键；分组键为单列时是标量，为多列时是元组
  • group：每次迭代得到的第二个值，即该分组对应的子 DataFrame
  • sort：是否对分组键排序，默认为 True；设为 False 可略过排序过程，略微提升速度

示例：

import pandas as pd

df = pd.DataFrame({
    '城市': ['北京', '北京', '上海', '上海'],
    '区域': ['东城区', '西城区', '浦东新区', '徐汇区'],
    '销量': [10, 20, 30, 40]
})

for key, group in df.groupby(['城市', '区域']):
    print(key, '->', group['销量'].tolist())
# ('上海', '徐汇区') -> [40]
# ('上海', '浦东新区') -> [30]
# ('北京', '东城区') -> [10]
# ('北京', '西城区') -> [20]

解释

for i, j in data.groupby(['城市','区域']) 中 i 是分组键（多键时为元组），j 是该组子表。可用于查看分组结构或做层级表头展示，但实际分析中应尽量避免循环。

有什么用

  • 调试时查看分组键与子表
  • 需要逐组做特殊处理时
  • 理解 groupby 的拆分结果

关键要点

  • i 为分组键，多键分组时是元组如 ('北京','东城区')
  • j 为该组对应的子 DataFrame
  • 可做出带层级表头的展示效果
  • Pandas 中应尽量避免 for 循环，除非万不得已

边界与易混淆

循环逐组处理性能差，能用 agg/apply 向量化解决就不要用迭代。

自测

多列分组时迭代变量 i 是什么类型？
元组，例如 ('北京','东城区')。
为什么实际分析不推荐遍历分组？
逐组循环性能差且代码冗长，聚合类需求用 agg 更高效。
