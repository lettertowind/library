广播兼容规则

不兼容广播 · 广播判断规则 · broadcast compatibility · 广播规则

从后缘维度起逐维比较，各维相等或其中一方为 1 才能广播。

用法

语法：两个数组从末尾维度开始逐维比较，相等或其中一方为 1 才能广播

参数：

  • 维度数不同：短数组左侧补 1 再比较
  • 某维长度为 1：可沿该维拉伸匹配另一数组
  • 任一维既不相等也不为 1：报 ValueError

示例：

import numpy as np

a = np.ones((2, 3))
print((a + np.array([1, 2, 3])).shape)       # (2, 3)，末尾维 3 匹配
print((a + np.array([[1], [2]])).shape)      # (2, 3)，列向量沿第 0 维拉伸
print((a + np.ones((3,))).shape)             # (2, 3)
# a + np.ones((2,)) 会报错：末尾维 3 与 2 不兼容

解释

两个形状不同的数组要直接加减乘除，NumPy 会先做一次兼容性判断：从形状最右边一维开始向左逐维对齐比较，每一维都要求「相等」或「其中一方为 1」，全部通过才会自动扩展并计算。只要有一维不满足，整个运算直接报错，不会做部分计算。它是判断「形状不同能不能算」的唯一标准，而不是看两个数组差几维、前面几维是否相同。

有什么用

  • 判断两个不同形状的数组能否直接运算
  • 解释 ValueError: operands could not be broadcast 报错的根因
  • 用 reshape 主动调形状来凑成可广播的形式

关键要点

  • 比较方向固定：从最后一维（后缘）开始，向左逐维推进
  • 每一维必须相等，或其中一方为 1，二者满足其一即可
  • 任意一维不满足条件，整体广播失败并直接报错
  • 前导维度相同不能弥补后缘维度的不匹配
  • 维度个数不同时，维数少的一方在左侧补 1 再逐维比较
  • 扩展由 NumPy 自动完成，不需要手写扩展后的数组

边界与易混淆

常见误解是「形状不同就能广播」或「前面维度相同就行」。(3,2,3) 与 (2,4) 前面有 (2,) 对齐但后缘 3 与 4 不等且都不为 1，因此无法计算。

自测

点开看答案，先自己想一想

形状 (3,2,3) 与 (2,4) 的两个数组能否相加？为什么？
不能。从后缘比较，3 与 4 不相等且都不为 1，广播不兼容，前面的 (2,) 对齐也无法弥补。
形状 (5,1) 与 (1,4) 能否广播？结果形状是什么？
可以。后缘 1 与 4（含 1）、次维 5 与 1（含 1）均通过，结果形状为 (5,4)。
