知识库操作规则

AGENTS.md —— 任何 AI Agent 打开这个库时遵循的规则

这个文件是本仓库的操作规则。任何 AI Agent（WorkBuddy / Claude / Codex 等）在这个目录下工作时，先读它，按它办事。 人类不必遵循，但建议了解一下，便于判断 AI 做得对不对。

一、这个仓库是什么

一座用 Obsidian 承载的个人知识库，核心是概念卡片，不是文档堆。

一条视频或文章进来，会被拆成若干张卡片，每张卡讲清一个名词：定义、解释、用处、要点、边界、关联、自测。卡片之间用双链连成网，靠 MOC/ 和 概念索引.md 组织，不靠文件夹层级。

判断做得好不好的标准：能不能精准调用。存得多没用，找不到、连不上就是失败。

二、目录结构

路径作用谁动
概念/概念卡片，平铺，一张卡一个文件AI 写，人可改
分析/问答沉淀、专题综述、深度分析AI 写
MOC/领域地图，一个顶级领域一页AI 自动生成，勿手改
_在编/待摄入的新素材（BiliNote 等工具直接落这里）外部工具写入
_典藏/已摄入的原始素材，按月归档AI 移入，勿删
_废弃/下架或合并掉的卡片AI 移入，勿删
_馆务/脚本、配置、日志、报告AI 维护
首页.md / 概念索引.md导航，自动生成AI 重新生成

三、概念卡片规范

文件名 = 概念名 + .md，例如 提示工程.md。

---
term: 提示工程
aliases: [Prompt Engineering]
kind: concept
domain: 计算机/AI/大模型
tags: [概念/concept, 领域/计算机]
created: 2026-11-16
updated: 2026-11-16
---

# 提示工程

> 别名：Prompt Engineering

**一句话定义（40 字内，加粗）**

## 解释
2-4 句，说清是什么、解决什么问题

## 有什么用
- 场景

## 关键要点
- 3-5 条

## 边界与易混淆
适用范围、容易搞混的地方（可空）

## 关联
- [[大语言模型]] — 上位概念

## 自测
问题::答案（供间隔重复插件识别）

## 出处
- [标题](url) · 日期

字段约定：

  • kind：concept 概念 / method 方法 / tool 工具 / model 模型 / metric 指标 / person 人 / product 产品 / entity 实体（公司、组织）
  • domain：层级路径，最多 3 段，如 AI/大模型、数据分析/统计、计算机/办公软件/Excel。按学科归类，不按使用场景
  • aliases：英文名、缩写、常见错写。同名合并靠它命中
  • tags：至少带一个 概念/{kind} 和 领域/{domain第一段}
  • 领域独立规则：术语/概念极多的类别可以从上位学科中独立出来，直接做顶级领域。当前顶级领域：Pandas（220 张）、Matplotlib（118 张）、Numpy（86 张）、AI（74 张）、数据分析（67 张）、计算机（24 张）、知识管理（10 张）。新素材若属于这些领域，直接用顶级域名开头：Pandas、Numpy、Matplotlib 三者已从 数据分析 独立，不要再写 数据分析/Pandas 这种旧路径。某个子域长到几十张卡时，按此规则再次上移。

四、四个标准操作

1. 摄入素材

触发：用户说「摄入素材」「整理新素材」，或 _在编/ 有新文件。

优先执行托管脚本（一致性更好）：

_馆务\整理概念.bat
_馆务\整理概念.bat --dry-run   :: 只预览

脚本做的事：读素材 → 抽取 3-8 个概念 → 同名则补充、新名则建卡 → 刷新索引/MOC/首页 → 原件归档到 _典藏。

如果脚本不可用（环境变了、要特殊处理），可以手动执行，但必须遵守第三章的卡片格式，并在完成后更新索引。

2. 体检

触发：用户说「体检」。

_馆务\知识库.bat      :: 菜单选 2
_馆务\维护.bat audit  :: 命令行等价

检查六类问题：重复、矛盾、失效、错位、孤岛、缺链。只出报告，不动文件，报告写到 _馆务/报告/。用户确认后才执行合并或下架。

3. 问答与沉淀

触发：用户提问。

先检索相关卡片（术语命中优先），只根据卡片内容回答。卡片里没有的，明确说没有，不许编。

高质量回答要沉淀成 分析/ 下的卡片，格式：

---
title: 问题式标题
kind: analysis
domain: 所属领域
created: 日期
---

# 标题

> 问题：原始提问

## 结论

## 展开

## 依据
- [[相关概念]]

## 出处

沉淀后要在相关概念卡的「关联」里补一条指向这篇分析。

4. 合并与下架

_馆务\维护.bat merge 保留的词条 被并入的词条
_馆务\维护.bat prune 词条

永不物理删除。 合并的下场是移到 _废弃/，同时全库把 [[被并入]] 改写成 [[主卡]]，别名补进主卡 aliases。

五、硬性规则

  1. 按学科归类，不按场景归类。 禁止 学习 生活 干货 杂谈 其他 这类类目。
  2. 一个概念一张卡。 观点、论述写进卡片的要点，不单独建卡。
  3. 同名即合并。 匹配顺序：文件名 → term → aliases。命中就追加，不新建。
  4. 不删只废。 任何卡片、素材都移到对应目录，不 rm。
  5. 改动前先说方案。 批量操作、合并、下架，先打印将要做什么，等用户确认。
  6. 双链可以指向不存在的卡。 允许 [[注意力机制]] 这种待建链接，首页.md 会汇总成「待补全词条」。
  7. 不覆盖人的手写内容。 补充只能追加章节，改写定义要用户明确同意。

六、不要做

  • 不要把所有视频笔记塞进一张「视频笔记」卡
  • 不要为了让数字好看而硬凑概念
  • 不要在 MOC/ 首页.md 概念索引.md 里手写内容（会被覆盖）
  • 不要把 _典藏/ _废弃/ 当垃圾清空，那是追溯凭据
  • 不要在没确认的情况下批量删改超过 5 张卡片

七、脚本清单

脚本作用
_馆务\知识库.bat中文菜单，六个功能的总入口
_馆务\整理概念.bat摄入（可加 --dry-run）
_馆务\维护.bataudit / merge / prune / ask / rebuild
_馆务\后台整理.bat常驻监听 _在编，自动摄入
_馆务\config.json模型配置（api_key / base_url / model）

脚本用的是打包在 BiliNote\backend\.venv 里的 Python 环境，里面有 openai SDK。
